# ADR-0120: 上游吸收纪律——A 类冲突本地优先 + 冻结清单

日期：2026-09-13 ｜ 状态：已采纳

## 背景

ADR-0117 定下「按块吸收上游纯增量」的路线后，2026-09-13 的分层审计（`.scratch/upstream-compare/`）暴露出两类必须事先定规矩的东西：

1. **A 类 15 项直接冲突**：两边对同一处做了互斥设计（本地 password 并入 encrypt ↔ 上游回拆 password-vault；本地 `todo`/`literature` ↔ 上游 `memo`/`knowledge`；本地 `diary-wall` 独立域 ↔ 上游升格进 `diary`；`core/mobile.ts` 上游删掉了本地 19 处在用的导出……）。这些冲突项如果跟着某个「纯增量块」一起进来，就会顺手把本地实现覆盖掉。
2. **三项数据层不可逆风险**：`secondbrain.vec` 本地版本号 v10（含 hash 迁移分支）↔ 上游 v9（版本不符即清库重嵌）；上游 pomodoro `trimHistory` 会在下一次落盘时**永久写掉**超过 7 天的历史；上游 `core/storage.ts` **没有** ADR-0116 的空读防护、读重试与写前留底——它正是 2026-09-11 review.json 清库事故的对策，而上游那条路径仍是「解析失败 → 重建默认值」。

## 决策

### 一、A 类冲突：一律本地优先

1. **A 项不进吸收范围**。「上游没有本地的东西」（如 ADR-0116 空读防护）不算冲突，属于本地保留，无需处置。
2. **例外通道唯一**：若某块吸收**必须**动本地既有契约（导出签名、设置键语义、CSS 契约、数据格式）才能落地，该块**降级为独立票 + 单独 ADR**，不得夹在「纯增量」块里带进来。
3. 判断依据是 ADR-0117 的两条硬门槛，不因「上游看起来更新」而放宽。

### 二、冻结清单（吸收时禁止被上游同名文件覆盖）

| 冻结对象 | 理由 |
|---|---|
| `src/core/storage.ts` | ADR-0116 空读防护 + 读重试 + 写前留底；上游无此机制，换掉即等于拆掉清库事故的对策 |
| `src/core/mobile.ts` 的 `applyMobileWindowFullscreen` | 上游已删除该导出，本地 **19 个文件**在调用；覆盖是编译级中断 |
| `src/diary/` 整套写链路（日记前导区、`# 随笔` 章节模型、写前守卫） | 上游 `src/diary/` 是**同名不同物**（上游把升格后的回忆墙放进该目录名）；禁止整目录覆盖 |
| `src/secondbrain/vector-store.ts` 的版本常量与迁移分支 | 本地 v10；上游 v9 会把本地库判为过期并清空重嵌 |
| `src/pomodoro/` | 不引入上游 `trimHistory`（7 天窗，落盘即永久截断，不可逆） |
| `src/literature/data.ts` 的数据文件名 | 不生成 `knowledge.json`（命名见 ADR-0118） |
| `src/encrypt/` | 本地并库实现；不引入上游 password-vault 回拆 |
| `src/todo/` | 本地命名与实现；不引入上游 memo 正名 |

### 三、数据层「三不」

不迁文件名、不裁历史、不动向量版本号。将来若确要动其中任何一项，先出独立票，内容必须包含**备份方案 + 就地迁移 + 回滚路径**，并通过评审才动。

### 四、吸收通例

一次只搬一块；每块独立 ticket；进本地基线前过完成门禁（`pnpm test` + `pnpm exec tsc --noEmit` + 构建验证）；起步阶段串行单分支，不并行 worktree（吸收多涉及 `core/` 共享文件，并行必撞）。

## 理由与边界

- **为什么本地优先**：本地这些实现几乎都是踩坑换来的——`storage.ts` 出自 4.9MB 被清成 `[]` 的事故、`mobile.ts` 那个导出牵着 19 处调用、`vec` 版本比较牵着远端 Ollama 重嵌成本。用「上游更新」当理由去覆盖它们，是拿已知教训换未知收益。
- **边界一：清单只管吸收**。这是「禁止被上游覆盖」的清单，**不是**本地架构永久冻结；本地自己演进这些文件不受本 ADR 约束。
- **边界二：不追平**。上游有而本地不需要的能力（RSS 源、daily brief、「通知」之外的横切偏好等）不因存在就吸收。

## 影响

- 后续每张吸收票的自检项：**是否触碰冻结清单**（触碰 → 走例外通道拆票）。
- 与 ADR-0117（路线）、ADR-0118（命名）、ADR-0119（文档命名空间）共同构成吸收工作的四条前置规则。
- 审计产物 `.scratch/upstream-compare/上游差异审计.html` 的 A/B/C 分类是本清单的事实来源。
