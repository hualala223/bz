# ADR-0111：日程规划支持「当日 / 明日」——入口选择 + 双标记重复检测

## 背景

「日程规划」自 ticket 245 从 QuickAdd 宏整合进 diary 域以来只有一种行为：**写死为明天**。入口是命令 `bz-diary-plan`（名为「日程规划（明日日记）」）与日记面板头部 🗓️，落到 `planTomorrow()`：`moment().add(1,'day')` → `addEntry(明天, 当前 HH:mm, ['日记'], buildPlanContent())`。

用户提出：点「日程规划」后应先出现「当日 / 明日」两个选项，两个选项生成的日记内容**完全一样**，唯一差别是落盘日期（今天 / 明天）。

改造过程中发现一个已存在的判重缺陷：`planTomorrow()` 用 `PLAN_MARKER = '### 代办事项'` 单标记判「该日已有规划」，而 issue 247 换血进来的「当日待办事项」捕获（`daily-capture.ts` 的 `TODO_HEADING`）**与它逐字同值**——往当天日记 `### 代办事项` 小节追加行是它的正常行为。于是：

- 现状下（只写明天）问题不显形，因为待办捕获只写当天、判重却查明天；
- 一旦支持「当日」，当天用过待办捕获 → 日记里必有 `### 代办事项` → 「当日」规划被判为"已有规划"直接跳过，**新功能上线即哑火**。

## 决策

**1. 入口先选目标日期。** 新增 `openPlanPicker()`：经 `openFlowDialog` 弹两动作「当日 / 明日」，选中后调 `planDiary(target)`；遮罩点击 / ESC 按取消语义 resolve `undefined` → 不创建任何条目。两动作不标 `cta`，默认焦点落在最后一个动作（= 明日），**回车即改造前的旧行为**。

**2. 两目标共用同一模板，只有日期不同。** `buildPlanContent()` 三段（`### 代办事项` / `### 完成情况跟踪` / `### 备注`）逐字不动；`planDiary(target)` 由纯函数 `planDate(target)` 决定落盘日期。条目标题 `# 📖 HH:mm` 仍取**当前时刻**（不按目标日期改写），保证两目标产物除日期外完全同构。

**3. 命令契约：id 不变、名称与行为变。** `bz-diary-plan` 保留（铁律 2：id 是外部裸调用约定），命令名与面板按钮提示由「日程规划（明日日记）」改为「日程规划」，行为由"一键明日"变为"弹选项"。`planTomorrow()` 导出退役（内部模块，无外部调用方；测试同步改走 `planDiary('tomorrow')` / `openPlanPicker()`）。

**4. 重复检测收紧为双标记。** 判「该日已有日程规划」= 同时命中 `PLAN_MARKER`(`### 代办事项`) 与新增 `PLAN_TRACK_MARKER`(`### 完成情况跟踪`)。待办捕获只写前者，故不再误伤；判定抽成纯函数 `hasPlan(entries)`，node 可测。

**5. 通知文案随目标走。** 「已在 YYYY-MM-DD 日记中创建日程规划」不变（含日期，无需区分）；已存在提示改为 `${当天|明天}（YYYY-MM-DD）已有日程规划，不再重复创建`。

## 后果

- 「当日」在用过「当日待办事项」的日记上可用（回归用例：单 `### 代办事项` 不算已规划）。
- **历史副作用**：只含 `### 代办事项` 而没有跟踪表的手写日记，会被判为"未规划"从而再建一份。代价可接受（多一条可自行删除的条目），换取的是不再与捕获行同名冲突。
- 把 `bz-diary-plan` 绑到快捷键或命令面板的用户：从"一键写明天"变为"弹两个选项"，多一次点击（默认焦点在明日，回车直达）。
- 不改动任何磁盘数据格式：模板正文、日记文件结构、frontmatter、命令 id 全部冻结不变。

## 备选（未采纳）

- **三动作（当日 / 明日 / 取消）**：语义更显式，但多一个按钮、走另一套按钮 id/类名，且两动作已能取消（遮罩 / ESC），多一次点击无收益。
- **给规划正文加专属标记行（如 `<!-- bz-plan -->`）判重**：最精确，但改动了写入磁盘的正文——与用户"模板完全一样"的要求冲突；且历史规划条目都没有该标记，会全部被判为"未规划"。
- **维持单标记 `### 代办事项` 判重**：当日功能在用过待办捕获的日记上点不动。
- **另加 `bz-diary-plan-today` 直达命令、`bz-diary-plan` 留作明日**：命令表膨胀，且与用户要的"点了再选"形态不符。
- **明日条目用固定 `00:00`/`08:00` 时间戳**（避免 23:50 规划明天出现 `# 📖 23:50`）：破坏"两目标模板一致"，且 `00:00` 会排到当日条目的最前面。

## 修订（ADR-0112）

本 ADR 的**落盘链路**部分已被 ADR-0112 取代：日程规划不再走 `addEntry` 条目链路（条目形态 `# 📖 HH:mm` + 三段），改为**按日记模板建文件 / 原样补写**，产物为模板骨架形态（与用户的 QuickAdd 宏 `日程规划.js` 同源同形）。

**仍然有效**的部分：

- 入口 `openPlanPicker()` 的两动作、「默认焦点 = 明日」与取消语义；
- 命令 `bz-diary-plan` 的 id 不变、名称改「日程规划」；
- 判重**双标记口径**（`### 代办事项` + `### 完成情况跟踪` 同时命中）——判据数据源由「解析出的条目」改为「文件原文」。；
- 通知文案随目标走「当天 / 明天」。

被取代的部分：`planDiary` 内部实现（`addEntry` → 模板文件读写）、`loadAll` / `diaryDataMap` 前置加载（文件级写入不再依赖内存映射）。
