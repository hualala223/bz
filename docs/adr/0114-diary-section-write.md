# ADR-0114：写日记 / 复盘改为「按小节落块」，退役日记解析检测工具

## 背景

ADR-0112 之后，「日程规划」产出的是**模板骨架形态**的日记文件（`# 睡眠相关` / `# 随笔` / `# 新闻联播内容记录` / `# 日常行为记录` / `# 日程规划` + 三段，ADR-0113 提级），而「写日记」与「每日复盘」当时仍走**条目模型**（`addEntry` → `# emoji HH:mm` 条目标题 + 整文件重写）。两条写入路径的产物形态南辕北辙：

- 条目模型下，写日记的内容落在「条目区」，标题是 `# 📖 20:30`，会被日记面板列表、标签筛选、回忆墙、智能猫（`smartcat/diary-source`）与今日回顾同时解析出来；
- 用户的实际用法是：每天先跑「日程规划」拿到当天/明天的日记文件，之后写日记只是**往这份骨架里填内容**。

用户的原话（三段要求）：

> 以后日记的文件模板都是根据「日程规划」得到的模板定文件内容格式，然后以后「写日记」功能得到的内容，都放在 `## 随笔` 下面放置，复盘除外，复盘仍旧按照原本该怎么放就怎么放。

> 我不想在日记面板列表、标签筛选、回忆墙、smartcat 这些什么里面看到，那个什么日记解析功能最好是给我取消，我不希望我的日记被解析。

澄清后确认的四点：

1. **写日记 = 往 `# 随笔` 小节末尾追加一块**（不再是条目）；
2. **复盘 = 往 `# 当日复盘` 小节末尾追加一块**（多条复盘按时间顺序堆在同一小节下）；
3. **「检测日记解析」工具取消**（用户不希望日记被解析/被工具盯着修）；
4. **存量文件一律不动**（ADR-0113 决策 3 延续）。

关键约束：条目头条正则在仓库里有**四份独立副本**（`diary/parser.ts` 的 `HEADING_RE`、`diary-wall/parser.ts`、`smartcat/diary-source.ts`、`recap` 复用 `parseFile`）。要满足「这些内容不出现在那四个消费方里」，**就不能再用 `# emoji HH:mm` 这个头条形态**。

## 决策

**1. 写日记落 `# 随笔`，块首行为加粗行（非标题）。**

```
# 随笔

**✍️ 20:30**

今天下午去河边走了走，风很大。
```

- 块首行 `**✍️ 20:30**` 是**加粗行不是标题**，四份头条正则（`^#\s*emoji\s+HH:mm`）一律不命中 → 内容自然不进日记面板列表 / 标签筛选 / 回忆墙 / 智能猫 / 今日回顾。
- 多选类型时 emoji **连写**（选「随笔 + 梦」→ `**✍️🌙 20:30**`），与旧条目标题的做法同源，只是外壳从 h1 换成加粗。
- 正文原样保留（仅 trim 首尾），正文为空时只留块首行。

**2. 每日复盘落 `# 当日复盘`，块首行为 h2 时间分隔标题。**

```
# 当日复盘

## 🪞 21:40

### 触动点
#### 描述经过（具体场景）
- 
...
```

- 小节名占 `#`，时间分隔行占 `##`，复盘内层模板（`### 触动点` / `#### …`）**保持不动**——这是 0113「复盘只提首行」的延伸。
- `REVIEW_TEMPLATE` **去掉首行 `# 当日复盘`**：小节名由落点提供，模板再带一行会在文件里出现两个「当日复盘」标题。
- **多条复盘按时间顺序堆在同一小节下**（每个块自带 `## 🪞 HH:mm` 时间标题区分）。

**3. 落点小节缺失时的行为分两种（有意不对称）。**

| 落点 | 在骨架里 | 缺失时 |
|---|---|---|
| `# 随笔`（写日记） | 是 | **不建**——追加文末并弹 warning 说明（存量文件一字不改） |
| `# 当日复盘`（复盘） | 否 | **写时在文末新建小节**（用户原话「在日记文件最下面添加『当日复盘』」） |

**4. 复用单一「按标题小节插入」实现。**

`daily-capture.ts` 抽出 `locateSection`（标记定位 + 小节边界），两个入口共用：

- `insertIntoSection`——单行捕获（当日待办 / 日常行为记录，issue 247，格式冻结）；
- `insertBlockIntoSection`——**多行块**（写日记 / 复盘），带 `createIfNotFound` 开关，块前恒加一空行、块后按需补一空行。

「新层级优先、旧层级兜底」的两轮查找与「小节边界取**命中行实际层级**」的兼容口径（ADR-0113）因此只有一份实现，不会在两条写入路径之间漂移。

**5. 退役「检测日记解析」工具，但保留写前守卫。**

- 删除：日记面板 ⚙️ 设置里的「维护」组与「检测日记解析」按钮、`diary/ui/repair-modal.ts`、`diary/repair.ts` 及其测试、`styles.css` 里的 `bz-diary-repair-*` 样式、d3 直写门禁白名单里的 `repair-modal.ts` 条目。
- 四处指向该工具的文案（`store.ts` ×3、`recap/summarize.ts` ×1）改为**不指向工具的人话**。
- **写前守卫保留**（`writeFile` 遇到条目区无法解析行仍拒写）：它是保护存量文件不被吞行的唯一机制；只是不再引导用户去点一个已不存在的工具（用户不希望日记被「解析」，但也不想日记丢内容）。

**6. 「保存后进入编辑」降级为「打开该日期日记文件」。**

块模型下没有条目可跳（`jumpToEntry(newEntry, 'edit')` 失效），改为 `openDiaryFile(path)`——保住「保存后想接着补两句」的原始意图。设置项 `diaryJumpToEditAfterSave` 保留。

## 后果

- 写日记 / 复盘的内容**不再进入**日记面板列表、标签筛选、回忆墙、智能猫与今日回顾——这是用户明确要求的效果，也意味着这些内容**不能在插件面板里编辑/删除**（只能直接开文件改）。
- 面板列表会逐渐只剩存量条目（全库 621 个日记文件里只有 4 个含 `# emoji HH:mm` 头条），这是有意接受的空转，不是缺陷。
- `parseFile` / 条目模型（`addEntry` / `writeFile` / `deleteEntry`）**不删**：回忆墙、智能猫、今日回顾、加密域仍要读存量条目。
- 骨架标题（`# 随笔`）与块首行（`**✍️ 20:30**`）均不被头条正则命中，ADR-0110 的前导区口径不受影响。
- 新建日记文件仍由「日程规划」产出（ADR-0112），写日记本身不再建文件——文件不存在时会以「`# 随笔` + 块」起头新建一个最小文件。

## 备选（未采纳）

- **写日记改用 h3 标题（`### ✍️ 20:30`）**：同样能避开四份头条正则、且在 Obsidian 大纲里是真层级从属；但用户裁定用**加粗行**——加粗行连「标题」都不是，最彻底地避免被任何按标题工作的工具碰到。
- **放弃条目模型、清空面板**：会连坐回忆墙 / 智能猫 / 今日回顾 / 加密域四个消费方，且 621 个存量文件的读取链路无处安放。
- **把内容写进 `## 随笔` 并保留 h1 头条**：直接与「不想在那些地方看到」冲突。
- **删按钮同时删守卫**：存量文件里仍有畸形头条（如 `# 📖 9:33`），删掉守卫等于放弃防丢行保护。
- **给 `# 随笔` 也做「缺失即建」**：会在存量条目形态文件里凭空长出小节，违反「存量不动」。
