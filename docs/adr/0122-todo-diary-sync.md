# ADR-0122 · 加待办与日记「代办事项」双向同步（当日待办事项捕获退役）

日期：2026-09-13 · 状态：已接受（grill-with-docs 两轮决策，用户逐条裁决） · 关联：ADR-0092（todo 域为 memo.json 唯一属主）、ADR-0113（日记骨架层级上提）、ADR-0114（按标题小节插入单点）、ADR-0121 第 4 条（冻结范围内用户主动需求可正常立项）

## 背景

用户需求：打通「加待办」（`bz-todo-add`，写 `memo.json`）与日记文件 `## 代办事项` 小节——加待办时同步写进当天日记；勾选完成时日记同步打钩；当天未完成的自动顺延到第二天；待办按添加顺序编序号。

现状事实（file:line 可查）：

- 「加待办」→ 待办面板创建弹窗，只写 `memo.json`（14 字段冻结，无序号、无日期归属概念，仅 `created` 时间戳），与日记零联动（`src/todo/data.ts`、`src/todo/ui.ts`）；
- 日记 `## 代办事项` 另有独立命令「当日待办事项」（`bz-diary-todo-capture`）直接写冻结格式行 `- [ ] 内容-HH:mm`（`src/diary/daily-capture.ts`）；
- 勾选完成仅写 memo.json 的 `completed` 时间戳；无任何顺延机制（仅手动「延后 N 天」）。

## 决策（两轮 grill 裁决记录）

1. **换血：当日待办事项捕获彻底退役（Q1/Q7a）**。删除 `bz-diary-todo-capture` 命令与入口代码，smoke 测试 `EXPECTED_COMMAND_IDS` 64 → 63。日记 `## 代办事项` 的唯一写入者 = 本 ADR 的同步机制；冻结行格式 `- [ ] 内容-HH:mm` 的语义由新行格式继承。

2. **日记行格式与序号（Q2a/Q3a）**：`- [ ] <序号>. <标题>-<HH:mm>`（勾选后 `- [x] …`），`HH:mm` = 添加时刻。序号 = **该行写入当天日记的先后顺序，按天重排**：启动顺延的一批按原 `created` 时间排序排前拿 1..k，当天新添加的从 k+1 续号；中午才启动时顺延行接在当天已有最大序号后（Q10a），已写下的行永不重排。序号在日记侧是锚点，待办面板不显示序号（Q6）。

3. **同步不变量**：所有未完成待办条目，都在**今天**日记的 `## 代办事项` 小节有对应投影行。由三个触发点维护：
   - **添加**：面板新增条目 → 追加到今天小节末尾，序号 = 既有最大号 + 1；
   - **勾选**：面板完成 ↔ 日记打钩、面板恢复 ↔ 日记退回 `[ ]`（双向）；
   - **顺延（Q5）**：插件启动（onLayoutReady）及当天首次打开待办面板时，把**所有历史未完成**且今天日记尚无投影行的条目补写进今天小节（去重，只补一次）；今天日记文件缺失时按既有先例「小节标记 + 首行」建档，不预建明天文件（避免与 QuickAdd 模板建日记冲突）。

4. **双向同步边界（Q4/Q8/Q9 裁决，用户明示「都跟着改，不管是哪边」）**：
   - **改标题双向**：面板改标题 → 今天日记行文本同步改（保留序号/勾选态/时间后缀）；今天日记行文本被手动改 → 解析回面板标题；
   - **删除双向**：面板删条目 → 今天日记投影行删除；今天日记投影行被手动删 → 面板条目删除（走既有撤销通道，撤销 = 两边都恢复）；
   - **同步窗口 = 今天的日期文件（Q9a）**：历史日记是当天状态快照，永不回改、不触发反向同步；跨天投影行（昨天未打钩 + 今天顺延行并存）勾选只动今天的行。

5. **不动的部分**：`memo.json` 14 字段冻结不加项（序号由 `created` 当天排序与写入顺序推导，不落库）；面板「延后 N 天」、due、场景、优先级等既有功能照旧；历史日记（含已写的无号捕获行）原样保留，**无号行不参与匹配、不联动**；反向匹配靠「去掉序号前缀的 `标题-HH:mm`」与 `title + '-' + created(HH:mm)` 精确比对，不往日记行写 id；同日同分同标题的重复条目按行序一一对应。

6. **移动端同步**（用户明示要求）：同步链路全部为 vault 读写 + 既有同路径串行队列，无桌面专属 API；启动顺延挂 `onLayoutReady`（移动端同样触发），待办面板移动端全屏等既有规范不变。

## 后果

- todo 域新增日记同步模块：订阅 vault modify（日记目录过滤 + 去抖）与面板动作钩子；小节定位复用 ADR-0114 单点逻辑并扩展「小节内更新/删除行」纯函数；
- 回声抑制：本机制自己写入的日记修改不得反向触发面板变化（防循环）；
- 当天未启动插件则不顺延（无后台进程）；历史未完成条目会在下次启动/开面板时补进当天，不丢失；
- `EXPECTED_COMMAND_IDS` 与命令总数文档（64 → 63）同步修订，防文档漂移；
- 顺延行与当天新加行格式完全一致，不做「顺延」视觉标记（用户未要求，Q10 推荐口径）。

## 修订（2026-09-13 晚，实测缺陷反馈）

**序号续接认「一切编号行」，不只认插件行**。用户手打的编号行（`1.折腾…-08:20` 点号后
无空格、`9.…` 无时间后缀）原不被 `maxSeq` 认账，插件顺延误判小节为空、从 1 重新编号撞号。
修订：新增 `maxWrittenSeq`（`- [x] N.` 形态即占号，不要求空格与时间后缀）用于顺延/新增续号；
`parseProjectionLine` 点号后空格改可选（带时间后缀的手打行因此可参与勾选联动/去重）。
无时间后缀的手打编号行仍非投影行（不联动、不被改动），仅占号。「已写行永不重排」不变。
