# ADR-0112：日程规划改为「按日记模板建文件」

## 背景

ADR-0111 敲定了日程规划的入口形态（流程框选「当日 / 明日」）与双标记判重，但**落盘仍走 `addEntry` 条目链路**，产物是条目形态：

```md
# 📖 09:12

### 代办事项
...
```

用户报「你修改了我原本的日程规划的模板样式」——对照 vault 里的模板真源，问题属实：

- 用户的 QuickAdd 宏 `CONFIG/SCRIPTS/日常时间记录/日程规划.js` 做的是：**读 `CONFIG/TEMPLATE/模板-日记.md` → 末尾追加日程三段 → 新建文件**；目标文件已存在则只弹一句「已存在」直接返回。产物是**模板骨架形态**（frontmatter + `## 睡眠相关 / ## 随笔 / ## 新闻联播内容记录 / ## 日常行为记录 / ## 日程规划`），即 `我的/日记/2026-09-11.md` 那份（用户点名要的样式基准）。
- 插件版产出条目形态，**与宏产物不是一个东西**；条目模型整文件重写也**产不出**骨架形态。

字节级校验（2026-09-11 实测）：`模板原文 + "\n\n" + buildPlanContent() + "\n\n"` 与 vault 真文件**完全一致**（`COMPOSE_MATCH=true`）。

## 决策

**1. 落盘改为文件级原样读写，不再经过 `addEntry` / 条目模型。**

| 目标文件状态 | 行为 |
|---|---|
| 不存在 | 读模板 → `模板 + "\n\n" + 日程三段 + "\n\n"` → **新建文件** |
| 存在且原文已有日程规划（`### 代办事项` + `### 完成情况跟踪` 双标记） | 提示不重复创建，**一个字节不写** |
| 存在但没有日程规划 | **末尾补** `## 日程规划` + 日程三段，其余内容一字不动（已有 `## 日程规划` 标题则只补三段，不重复标题） |

`hasPlan` 的判据从「解析出的条目」改为「**文件原文**」（双标记口径沿用 ADR-0111）。

**2. 模板真源 = vault 里的 `CONFIG/TEMPLATE/模板-日记.md`。** 与宏同源：用户改模板文件，宏与插件同步跟随，不产生第二份真源；模板不可读（缺失/异常）时用内置兜底骨架 `FALLBACK_DIARY_TEMPLATE`（同构），不阻断创建。

**3. frontmatter 规整（相对模板原文的仅有改动，用户确认）。** 删除 `title`（模板占位残留 `"电视剧.md"`）、`date_creation` 改写为 `{目标日期} 00:00:00`，缺失则补一行。因此产物与 `2026-09-11.md` 的差异仅在这两行。

**4. 目录走插件设置 `DIARY_DIRECTORY`（默认 `我的/日记`）**，不用宏的硬编码路径；目录缺失逐段创建。写盘走 `core/storage` 同路径串行队列（键 = 日记文件路径），与 diary store 的 `writeFile` 互斥。

## 后果

- 产物与宏逐字节同形（除决策 3 的两行），用户点名的样式基准成为回归测试的断言基准。
- 规划文件与后续「写日记」写入的条目可共存（骨架留在文件头、条目追加在下，ADR-0110）；不再触发条目模型的整文件重写。
- **模板文件被清理**（`title` 行与非法 `date_creation` 行移除），其 4 个消费方——`日程规划.js`、`日记.js`、核心 daily-notes、QuickAdd——新建日记不再带上那两个脏字段；代价是**宏不再自动产出 `date_creation`**（插件会按目标日期填），宏已被插件取代，可接受。
- 「当日」可用：今天的日记通常已存在，此时按决策 1 的第 3 行补写（若那份日记已有规划则提示不重复，如模板形态的 `2026-09-11.md`）。

## 备选（未采纳）

- **把模板内容内置进插件、不读模板文件**：用户改模板不再生效，且宏与插件会产出两套渐渐漂移的样式。
- **继续走 `addEntry` 条目链路**：条目模型整文件重写产不出骨架形态，且写一次就把用户的模板骨架关系搅乱。
- **文件已存在时严格照宏「提示即返回」**：支持「当日」后今天的日记几乎总是已存在，该分支会让「当日」永远只弹一句"已存在"（用户选 B 的理由）。
- **不动模板文件的脏字段、逐字复制进产物**：每个新建日记都会带 `title: "电视剧.md"` 与秒数非法的 `date_creation: 2025-11-06 23:11:89`。
