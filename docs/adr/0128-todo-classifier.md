# ADR-0128: 待办三维分类器替换排序下拉（类别/优先级/时间）

日期：2026-09-22 ｜ 票：issues/298-todo-category-time-classifier.md ｜ 状态：已接受

## 背景

待办面板工具行的排序下拉（紧急优先/仅按到期/按创建，键 `memoSortMode`）只有单一排序视角；用户需要「必须/想要 × 重要/次要 × 紧急/不紧急」的三维组合筛选来定位待办。原「紧急优先」是排序语义（到期优先 + 重要优先），不是筛选器，两者不可互相替代。

## 决策

1. **三维组合筛选替换排序下拉**：面板工具行改挂分类下拉（11 项 = 全部 + 8 组合 + 按到期 + 按创建）；「紧急优先」从可选排序退役，其排序逻辑保留为内部默认排序（全部/组合视图下生效）。按到期/按创建并入分类下拉末尾，选中 = 全部 + 该排序。
2. **「时间」是独立标记字段，不从 due 派生**：紧急/不紧急是主观标记，与截止时间（due）语义正交——有远期 due 的事可以标记紧急，反之亦然。UI 标签沿用用户口径「时间」，术语表记为**待办紧急度**，Avoid 与截止时间混淆。
3. **数据向后兼容零迁移**：`TodoItem` 增 `category`（must|want，缺省 must）/`urgency`（urgent|not，缺省 not），`normalizeItem` 缺省补齐；memo.json 旧条目首次读到即落「必须/不紧急」，不写迁移脚本。约定字段 14 → 16（`MEMO_ITEM_FIELDS` 与 `checks-consistency.memoNormalize` 快照同步，这是体检双链的逐字对齐契约）。
4. **筛选状态不持久化**：每次打开面板重置「全部」。筛选是临时视角，跨会话粘住会造成「待办不见了」错觉（对齐 issue 268 播种逻辑的教训）；排序键 `memoSortMode` 因此退役（键保留兼容旧 data.json，面板不再读写）。
5. **不动存量交互**：左栏伪场景（今日/重要）、star 快捷切换、卡片视觉（不加新标记）、日记投影、file-sync 语义全部保留；composer 快速录入不挂新维度，新条目落缺省值，编辑器（类别行在优先级上方、时间行在下方）补标。

## 后果

- memo.json 新条目带 16 字段；旧版本插件读新文件多两个未知键（JSON 宽松读取，无碍）。
- 检查二（字段漂移）与检查四（同源一致性）的字段表同步扩到 16，未同步会误报——本 ADR 即对齐依据。
- 「紧急优先」字样从面板与设置页消失；用户如找排序，入口是分类下拉末两项。
