# ADR-0117: 与上游 yeshimei/bz 的分叉关系定位——选择性吸收

日期：2026-09-13 ｜ 状态：已采纳

## 背景

本仓库与 GitHub `yeshimei/bz` 同源分叉。共同祖先 `af7ed6b5`（2026-08-31），此后各自演化：

- 本地线（master tip `3a59fbef`）：QuickAdd 宏换血并入（collect 日常收集 19 条命令、日记每日捕获、review 搬迁重链）、存储空读防护（ADR-0116）、域重组为 `todo`/`literature`/`collect`/`diary-wall`/`launcher`/`quiz`。
- 上游线（tip `7b06f4b4`，2026-09-12）：域重组为 `memo`（ADR-0117 正名）、`knowledge`、`password-vault`（ADR-0109/0110 回拆），并新增锁屏（ADR-0124）、单源选择器（ADR-0127）、通知四项设置、全域换肤、行为单源/原型壳（ADR-0106）、首页条目化等整套设施。

2026-09-13 完成分层审计（产物在 `.scratch/upstream-compare/`），关键事实：

1. **历史不可 merge**：本地那次「并入上游线」的提交只有 1 个 parent——是内容复制，不是 git 合并。两线无共同后续历史，只能按内容比对。
2. **方向性分道扬镳**：多项域重组方向互斥（本地 password 并入 encrypt ↔ 上游 encrypt 回拆出 password-vault；本地 `todo`/`literature` ↔ 上游 `memo`/`knowledge`；本地 `diary-wall` 独立成域 ↔ 上游升格进 `diary`）。同名目录 `src/diary/` 两边装着不同东西。
3. **规模**：文件级本地 989 / 上游 1293；运行时命令 64 / 59；设置键 186 / 194。

## 决策

本地线定位为**同源分叉后的独立演进线**，与上游保持「单向取用」关系：

**三不做**

1. **不做 git merge**：历史不可 merge，且域级冲突面覆盖 core/diary/encrypt 等关键路径，合并成本与风险远高于收益。
2. **不回归上游主线**：本地独有资产过重（QuickAdd 换血 8 域、日记章节写模型、storage 空读防护、火山方舟等），回归等于丢弃近两周全部成果。
3. **不彻底分家**：上游那套纯增量设施（锁屏、单源选择器、通知四项、换肤、原型壳）有现成价值，弃之可惜。

**一做：按块吸收上游纯增量成果**

- 每块**独立 ticket**，可从上游摘取文件后在本仓库内适配；
- 进本地基线前必须过本地完成门禁（测试 + `tsc --noEmit` + 构建）；
- 吸收的两条硬门槛：
  - **不改本地数据契约**（铁律 1）：不得让 `CONFIG/STORAGE/*.json`、`我的/*.md`、frontmatter 格式因吸收而改变；上游若有数据改动，吸收时必须剥离或改为兼容读。
  - **不倒逼本地调用方改写**：若某块必须改既有导出签名/设置键语义/CSS 契约才能落地，则该块**降级为「需先立 core 前置票」**，不得混在一次吸收里夹带。

## 理由与边界

- **为什么不 merge**：两线对同一问题的设计决定方向相反（见背景 2），merge 会产生「谁覆盖谁」的语义决策，而这些决策本该逐项做、逐项留 ADR——正是本 ADR 之后的吸收流程在做的事。
- **为什么不整体回归**：本地 user-visible 契约（命令 id `bz-todo-*`/`bz-literature-*`、日记 `# 随笔` 章节模型、QuickAdd 收集入口）已被外部脚本与用户肌肉记忆依赖，回归的迁移成本落在用户身上。
- **边界一：单向**。本决策只约束「取用上游」。本地成果不反向推送上游（无该诉求，且会重新制造分叉）。上游后续新增的增量块，按同一流程再评估。
- **边界二：不追平**。本决策**不代表**本地线要向上游功能面看齐；上游有而本地不需要的东西（如 RSS 源、daily brief、密码本回拆）不因「上游有」就吸收。

## 影响

- 后续所有「吸收上游 X」的工作，先查本 ADR 的两条硬门槛；越界者拆票。
- 命名与文档编号的落地见 ADR-0118、ADR-0119。
- 审计产物保留在 `.scratch/upstream-compare/`（含 `report/*.json` 分层原始数据与《上游差异审计.html》）。
