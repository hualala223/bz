# ADR-0121 · review 与 diary 系功能绝对冻结（用户裁决）

日期：2026-09-13 · 状态：已接受（同日二次修订：第二次修订引入第 5 条「皮肤/外观层例外」，并作废第 3 条第 1 项） · 关联：ADR-0117（选择性吸收双门槛）、ADR-0120（纪律与冻结清单）

## 背景

上游吸收推进至 B 类功能块（issue 256 审计）。用户在对「可吸收功能菜单」（皮肤、解锁屏、首页条目化、剪藏本升级、文学域增强、选目录控件、内部质量）表态时明确：

> 我现在关注的我这边绝对不能改动的功能主要有两块，一块是复习相关功能，一块是日记相关功能。其他的都可以按照他的走。

同日补充澄清：

> 强调一下，日记相关功能，指的是跟日记有关的功能，包括最近修改和增加的什么日程规划、写日记、每日复盘等等等等的功能。复习同理。还有一个东西，现在的插件设置里的AI设置和小橘设置部分的内容不能改变。

## 决策

1. **review（复习）系与 diary（日记）系功能绝对冻结**。冻结范围按用户澄清为**功能语义**而非单一域目录：
   - diary 系 = diary 域本体 + 一切日记相关功能：**写日记、日程规划（bz-diary-plan 等）、每日复盘（recap 域）、回忆墙（diary-wall）、日记解析/来源（smartcat diary-source）**等现有及后续新增的日记相关功能；
   - review 系 = review 域本体 + 一切复习相关功能（复习交互模型、复习计划、复习数据）；
   - 功能行为、交互模型、数据读写、UI 结构一律不得因上游吸收而改动。此约束**高于** ADR-0120 例外通道——例外通道（独立票 + 单独 ADR）只豁免「动本地契约」的技术门槛，不豁免这两系。
2. **设置页「AI 设置」与「小橘设置」两个板块内容冻结**：现有配置项、文案、控件行为不变；吸收块不得在这两个板块内增删改配置项，也不得更换这两个板块内的控件实现（含其弹窗，如 ⚙️ 小橘设置弹窗内的记忆目录选择器）。
3. 涉及上述范围的上游块**裁剪后吸收**：
   - 全域皮肤：**改按第 5 条「皮肤/外观层例外」处置**（本条原表述「剔除 `diarySkin` 与任何 review 相干组」于 2026-09-13 用户二次裁决后**作废**）；
   - 解锁屏（`core/ui/lock-screen`）：只接 encrypt 保险库侧，**放弃**上游接 diary 弹窗的部分；
   - 选目录控件（setlist/path-picker）：**排除** AI 设置与小橘设置板块（含小橘弹窗）内的接入点，其余设置项照常；
   - 其余块（文学增强、剪藏本、首页条目化、内部质量）天然不触冻结范围，按常规纪律走。
4. 冻结范围自身的缺陷修复、用户主动需求仍可正常立项——冻结约束的是「吸收行为夹带改动」，不是「永久不可维护」。
5. **皮肤/外观层例外**（2026-09-13 用户裁决，取代原第 3 条第 1 项）：

   > 这几个板块的皮肤/外观层，如果上游有，可以直接按上游走——前提是功能逻辑和交互行为完全不变。不影响现有功能实现的皮肤可以改，影响现有功能实现的皮肤不能改。

   判据（**可核验**，逐条对照执行）：

   | | 允许（= 不影响现有功能实现） | 禁止（= 影响现有功能实现，该部分不吸） |
   |---|---|---|
   | 改动落点 | CSS 变量定义与取值、选择器与规则体；样式源文件（`src/<域>/styles.css`、`src/core/ui/tokens.css`、`src/core/ui/components.css`、`src/core/styles.css`） | DOM 结构与元素层级、控件类型与实现、事件绑定、交互流程、数据字段与读写时机、设置项键名/选项语义/默认值 |
   | 自检方法 | 把这段 diff **回滚**后，插件行为（点击、数据读写、命令、设置项语义）**完全不变**，只是外观退回旧样式 | 回滚后行为会变、或编译不过、或需要改调用方 |
   | 边界外推 | 纯 CSS 的暗色补齐、token 收编、滚动条隐藏、遮罩毛玻璃、配色/主题皮 | 借「皮肤」之名新增设置项、新增弹窗、新增控件、替换既有控件实现 |

   - **同票混合**：一个上游块若既有纯样式、又夹带上述禁止项，**只剥离纯样式部分**；剥离不干净或无法独立编译 → **整票放弃**，不做残缺移植。
   - **不得借道**：第 2 条的「AI 设置/小橘设置板块不得更换控件实现」**不被本例外豁免**——皮肤例外只放开样式，不放开控件（ADR-0127 路径选择器换控件仍属禁止）。

## 后果

- 每张吸收票的实现说明中必须含「review/diary 系零接触 + AI 设置/小橘设置零接触」核查项；
- 走第 5 条皮肤例外的票，另需附**回滚自检记录**：本次改动只落在样式源文件（列出文件清单），并说明回滚后行为不变的理由；
- 若某上游块无法在不触冻结范围的前提下吸收有意义的功能，宁可整块放弃或裁剪，不做残缺移植；
- 本 ADR 记入每次吸收票的验收清单，直到用户明示解除。

## 修订（2026-10-27，票 323）：「写日记界面」一处解冻

用户明示解除 diary 系冻结中的一格：**写日记弹窗的界面皮肤**允许移植上游 yeshimei/bz master（2a1a62b1，v1.33.x）的视觉（core uiModal 壳、米黄纸张材料、类型 chips、吸底栏、落纸动效），含随上游而来的 DOM 结构与控件实现变化。**流程仍为本地两步制（ADR-0109 保留，用户点名）**：第一步选类型点「添加」→ 第二步正文弹框 → 「确认」落日记正确位置。

**仍然冻结、不随本修订放开的部分**：

- 落盘行为与数据格式：ADR-0114 小节写入（`# 随笔` 落点、`**emoji HH:mm**` 块形态、缺失不建节追加文末）一字不动；
- 两步流程本身（用户裁定保留，不随上游改单步，也不改上游的「存后跳条目文件书写」）；
- 通知文案、「请至少选择一个类型」等冻结文案；
- `AddDialogPreset` 语义与每日触动点记录入口的落点路由；
- 冻结 id `add-diary-mask` / `add-diary-popup`（卸载清理表与 datetime-picker 同源依赖）。

依据：冻结系用户裁决，用户同权解除（动因=上游界面观感优于本地旧样式；经两轮澄清敲定「样式换上游、流程保两步」）。其余 review/diary 冻结范围与本 ADR 全部条款不变。
