# ADR-0110：日记前导区保留——条目模型与模板形态文件共存

## 背景

日期文件 `我的/日记/YYYY-MM-DD.md` 在真实 vault 里长期存在**两种形态**：

- **模板形态**：`---` frontmatter + `## 睡眠相关 / ## 随笔 / ## 新闻联播内容记录 / ## 日常行为记录 / ## 日程规划` 小节骨架（用户的 QuickAdd 模板/宏创建），正文与捕获行落在小节里。全库 621 个日记文件里 **153 个**是这一形态；
- **条目形态**：`# emoji序列 HH:mm` 标题块（`writeFile` 重写后的产物）。

条目模型（`parseFile` / `writeFile`）只认条目形态：`parseFile` 把「首个条目标题行之前的每一行非空内容」一律计入**未解析行**并静默丢弃；`writeFile` 又按内存 map **整文件重写**。于是：

1. 早于守卫的版本：写一次条目就把 frontmatter 与整份小节骨架**抹掉**（样例：`2026-09-10.md` 已无骨架），连带让「日常行为记录/当日待办事项」捕获失去小节落点（退化为文末追加）；
2. 引入 P0 写前守卫（上游并入）后：这类文件整篇被计为未解析行 → **守卫拒写**。

第 2 条的实测症状（2026-09-11，用户报障）：当天文件是模板形态共 28 行非空内容，全部计为未解析行 → 「写日记」「每日复盘」「日程规划」等一切走 `addEntry` 的入口全部失败，提示：

> 「2026-09-11」有 28 行内容无法解析，本次修改没有写入文件……请先在日记本设置中运行「检测日记解析」修复后再试。

而**提示指向的修复工具救不了这种文件**：`scanUnparsed` 把整篇列为「需手动处理（28 行）」且只提供跳转，无任何可执行动作——守卫与修复工具互相指认，形成死锁。

铁律 1（数据格式冻结）保护的是既有数据**可读**，不是保护「写一次丢一次」这个既有缺陷；CONTEXT 旧文里「条目模型 P0 写前守卫会拒绝含未解析行（模板形态）的文件」是把缺陷写成了约定，实际不可用（用户每天都写不出日记）。

## 决策

**把日期文件分成「前导区 + 条目区」两区，前导区在写回时原样保留。**

- **前导区**：文件开头到首个**疑似条目标题行**之前的全部内容（frontmatter、`## 小节` 骨架、QuickAdd 宏写入的正文）。
  解析器不为它产出条目，但 `writeFile` 全量重写时把它**原样拼回文件头**——条目永远追加在骨架之后，不再抹掉任何用户内容。
- **疑似条目标题行**（前导区边界，`findEntryRegionStart`）：合法形 `# emoji HH:mm`、缺空格形 `# 🤝02:43`、时间非两位形 `# 📖 9:33`（后两者正是修复引擎 R1/R2 的修复对象）。**边界行本身仍属条目区**——它的不合规形态照旧交「检测日记解析」修复，不会被前导区吞掉。
- **未解析行口径收窄**：`parseFile` 的 `onUnparsed` 只统计**条目区内**无法归属的行（时间越界标题行、条目内「空行 + `# `」截断后的孤行）。前导区不统计——它不会丢。守卫、`loadAll`/`refreshFile` 警告、`recap/summarize` 写前预检、`repair.ts` 的清单口径全部自动随此单源收窄。
- **`deleteEntry` 清空时**：前导区存在 → 只收回条目区、文件保留（不删用户模板骨架）；无前导区（插件自建文件）→ 维持原「整文件删除」。
- **单源**：三款标题正则与边界判定只在 `parser.ts` 定义并导出，`repair.ts` 改为导入（原先两处复制，属口径漂移隐患）。

## 后果

- 模板形态文件**可写**了：骨架留在文件头、条目追加在下，两形态在同一文件内共存；用户模板/宏与该插件不再互相破坏。
- 每次写盘会顺带把前导区做「首尾空行收敛」（行内容与行内空白一字不动），故模板形态文件的 headline 之后不会累积空行。
- `未解析行` 的含义变了（不再是「首个条目之前的行」），登记在 CONTEXT「未解析行」「日记前导区」两词条；ADR-0054 的修复边界（只修不合规头行）不受影响。
- 行号戳带前导区偏移（`preambleOffset`），`deleteEntry` 的行号定位在两种形态下都正确。
- `diary-wall`（回忆墙）是只读派生视图、无写路径，其 parser 副本不收编。

## 备选（未采纳）

- **保持拒写 + 强化修复工具**：让「检测日记解析」提供「把骨架包装成条目」「删除游离行」等动作。仍是让用户为工具的缺陷买单，且每天都要人工过一道门。
- **条目模型接管文件（保持抹掉骨架）**：等于承认用户模板与其捕获工作流作废，且丢失不可恢复。
- **无前导区概念、改为「写前把非条目内容并进首条目正文」**：会改变条目内容语义，且首个条目锚点漂移。
