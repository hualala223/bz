# ADR-0131: 「每日复盘」更名「每日触动点记录」——入口改文案、落点改标题、旧落点不兼容

日期：2026-09-24 ｜ 票：issues/302-daily-review-rename-touchpoint.md ｜ 状态：已接受

## 背景

用户点名：把插件里的「每日复盘」改成「每日触动点记录」，其他保持不变。该功能是 diary 域 daily.ts 的写日记弹窗预填入口（`openReviewDialog`，原落 `# 当日复盘` 小节），与 recap 域「今日回顾」面板无关（后者不动）。模板核心小节本就是 `### 触动点`，更名后名实一致。

本功能属 ADR-0121 冻结的 diary 系——冻结语义是「上游吸收不得动它」；本次为用户直接裁决的本地演进，冻结照旧成立，但会产生一处新的上游 divergence。

## 决策

1. **显示名全改**：命令名（`bz-diary-review` 的 name）、日记面板 🪞 按钮 tooltip、首页快捷入口 label、通知文案小节名 → 「每日触动点记录」。
2. **命令 id 不变**：`bz-diary-review` 是外部裸调用约定（铁律 2），只改显示名。
3. **落点小节标题改**：`REVIEW_HEADING` = `# 当日复盘` → **`# 当日触动点`**（用户原话「在日记文件最下面添加『# 当日触动点』标题，然后将添加的触动点按顺序放在该标题下面」——注意文件内标题与显示名不同字，属用户明确指定的双轨：界面叫「每日触动点记录」，日记文件里叫「当日触动点」）。**不批量迁移旧文件**。
4. **旧落点不兼容（二次裁定，推翻当日早先的别名兼容方案）**：初版曾给 `daily-capture.ts` 定位层加 `LEGACY_REVIEW_HEADING` 别名（旧 `# 当日复盘` 命中即追加进旧小节）；用户实测发现触动点写进了旧「当日复盘」小节，当场裁定**不再往旧小节追加**——写入一律落 `# 当日触动点`（缺失文末新建，已有按时间顺序追加在节内末尾），旧 `# 当日复盘` 小节一字不动、不迁移。别名管道（`findMarkerLine/locateSection` 的 `aliases` 参数）整体回收，`locateSection` 回到「精确层级优先、旧层级兜底」两轮查找的原貌。
5. **标签更名**：`REVIEW_TAG` 与 `DEFAULT_TAGS_CONFIG` 键 复盘 → 触动点（emoji 🪞、模板正文 `### 触动点` 起的层级全部不动）。旧条目 `## 🪞 HH:mm` 的 emoji 经 `emojiToTagMap` 归到新名，纯展示语义。
6. **建节行为不变**：触动点记录小节不在骨架里、缺失写时新建；写日记 `# 随笔` 的「缺失不建」口径不动（ADR-0114 原样）。

## 后果

- 旧文件行为：有 `# 当日复盘` 的日记**不再**往里追加；写入固定落 `# 当日触动点`（文末新建或节内按顺序追加，测试覆盖）。一个文件里旧标题与标题并存是合法稳态，不做迁移工具。
- 与上游血统 divergence +1（daily 域文案与落点标题），后续吸收票需把本文件列入豁免清单（ADR-0121 冻结域）。
- 数据零迁移：`CONFIG/STORAGE/*.json`、日记 frontmatter 均不动；仅日记文件内的小节标题用新文字。
