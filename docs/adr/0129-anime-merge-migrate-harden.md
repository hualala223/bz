# ADR-0129: 动漫细分退役 + 娱乐目录迁移加固

日期：2026-09-22 ｜ 票：issues/300-anime-merge-migrate-harden.md ｜ 状态：已接受

## 背景

两个独立问题同日裁决：

1. 动漫组是唯一带细分 tag 的顶级类型（表单类型行显示 日漫/国漫/美漫 三个 chip，fm 记细分值）——用户质问「统统不是动漫吗？干什么要拆开？」。细分粒度无筛选使用价值（用户不用），且与其余六组「类型=组名」口径不一致（上游 yeshimei/bz 遗留设计）。
2. 票 292 的娱乐目录启动迁移在实机上只完成一半：设置值平移落盘（data.json 16:42），物理目录 rename 未发生（我的/影视 33 条仍在、我的/娱乐 不存在），且 data.json 此后再无落盘——与用户报告「插件开关打不开」时间吻合，根因假设为 renameFile 在 N 盘（映射网络盘 + 外部同步进程）上失败抛异常、中断 onLoad。

## 决策

1. **动漫细分退役**：`TYPE_GROUPS` 动漫组收敛为 `['动漫']`；`LEGACY_TAG_MAP` 加 `日漫/国漫/美漫 → 动漫`（读侧归一显示，fm 原值不改写——同票 293/299 先例，零数据迁移）；`GROUP_SUBS_OF` 动漫清空（表单单 chip）；AI 推荐 `GROUP_DEFAULT_TAG` 动漫:'动漫'。七项顶级类型中仅公开课保留 TED 细分（原设计，未在本次裁决范围）。
2. **迁移 rename 失败降级**：`migrateCinemaFolder` 的 renameFile 包 try/catch——失败时 `console.error` + Notice「请手动重命名文件夹」，设置值平移照常生效并返回 true，**不中断插件加载**。目录归位动作交给用户手动完成（Obsidian 右键重命名，双链自动更新）或下次启动迁移自动重试。

## 后果

- 命令数不变；smoke 计数不动。
- 旧 日漫/国漫/美漫 条目显示、筛选归「动漫」组；编辑保存后 fm tag 才写「动漫」。
- 插件在 rename 失败场景下可正常加载，娱乐面板空库但可用；用户手动重命名后条目自动出现（file 事件触发重建）。
- migrate.test 新增 rename 失败降级用例；data.test 补归一断言；ui.test 美漫 seed 留作读侧归一活体验证。
