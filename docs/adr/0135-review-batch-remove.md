# ADR-0135 — 复习计划批量移出：勾选清单 + 单条口径对齐（摘确认、落排除名单）

**日期**：2026-10-26　**票**：320　**状态**：已采纳

## 背景

用户需求：把已有复习计划的文件移出计划，支持批量选择——可单个勾选，也可一键全选。此前清理 review.json 的唯一入口是 ⚙️ 设置「复习条目管理」组的逐条「移出」（票 168，ADR-0077 面板退役后的收敛面），一次只能移一条，无批量能力。

本票属用户主动需求，走 ADR-0121 例外条款（冻结域的主动立项允许；review.json 格式、「按数量复习」行为零接触）。

两处「文档 vs 代码」矛盾一并裁决（grill 会核出）：

1. CONTEXT.md「排除笔记」词条早写明「手动移出（监听目录内）落排除名单」，但单条移出代码（ui.ts）从未写过名单——只有删除联动（watch.ts）写。属代码欠账，非词条空想。
2. 效率整改 5（notice.ts）书面口径「接了 notifyUndo 的移除不再二次确认」且标注 review 先行，但单条移出实际仍是 确认弹窗 → 移除 → 撤销 双保险。

## 决策

**术语**：沿用 CONTEXT.md 既有词「移出」，不造「取消」新词——功能名「批量移出」，命令「批量移出复习计划」`bz-review-remove`。

**批量弹窗**（新 `src/review/batch-ui.ts`，attach 域 `openMovePreview` 可勾选清单范式）：

- 双入口：⚙️「复习条目管理」组「批量移出…」按钮（空计划隐藏）+ 命令面板直达；弹窗内完成单选/全选/执行。
- 默认**全不选** + 表头「全选」复选框（部分勾选呈半选态）——encrypt 域票 18 先例：危险批量操作默认不选中；底部按钮实时「移出 N 条」、0 禁用。
- 挂起条目（文件缺失）参与勾选与全选——批量清挂起正是顺手收益。
- 执行 = `removeItems` **一次读改写单次落盘**（区别于 attach 逐文件 rename，故无 i/N 进度通知）→ 监听目录内且未排除的路径写排除名单（与删除联动同口径）→ 文件树染色回退 → `notifyUndo`。
- **不再二次确认**：逐条勾选本身即明确表态，撤销兜底覆盖误操作（效率整改 5）；撤销 = `restoreItems` 按计划序原样插回（阶段/排期/历史零丢失）+ **仅解除本次新增**的排除记录（预先存在的排除不动）。

**单条移出同步对齐**（同一列表不允许两套「移出」行为）：摘确认弹窗（效率整改 5 落地）+ 监听目录内移出补写排除名单（词条语义补齐）；撤销回调同样只解除本次新增。

## 后果

- COMMANDS 表 81 → 82（总命令 83 → 84）；smoke `EXPECTED_COMMAND_IDS` 同步。
- 数据层新增 `removeItems` / `restoreItems`（均入 per-path 串行队列，P1-33 口径不变；批量撤销一次落盘，N 条不再 N 次写）。
- 排除名单语义与 CONTEXT.md「排除笔记」词条最终一致：单条移出、批量移出、删除确认三类表态均落名单；词条文字零改动。
- 弹窗期间计划可能被会话/自动加入改动：以 `removeItems` 实际移除结果为准（返回值即撤销快照），数量文案与真实一致。
