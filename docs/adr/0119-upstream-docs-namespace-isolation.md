# ADR-0119: 上游文档命名空间隔离（ADR / issue 编号不再撞号）

日期：2026-09-13 ｜ 状态：已采纳

## 背景

两线分叉后各自继续发放 ADR 与 issue 编号，撞号已经发生且会持续：

- **ADR 局部撞号**：`0077`/`0078`/`0079` 是本地多发的同号文件（内容不同）。
- **ADR 彻底撞号 0106~0116**：本地 `0106`=日记隐私门、`0107`/`0108`=collect 域、`0109~0114`=日记弹窗与章节、`0115`=review 搬迁重链、`0116`=存储空读防护；上游 `0106`=行为单源、`0107`/`0108`=剪藏本、`0109`/`0110`=密码保险库回拆、`0111`/`0113`=影院、`0112`/`0116`=知识盒、`0114`=第二大脑、`0115`=回忆墙升格。裸写「ADR-0110」已指向两件事。
- **上游 0117+ 继续并跑**：上游已发到 `0127`，本地从 `0117` 起续发，仍有 11 号重叠区间。
- **上游自身编号也不干净**：`0110` 有两个文件（`0110-password-vault-single-source.md` 与 `0110-secondbrain-prototype-rewrite.md`）、`0125` 缺号、`ADR-0124-shared-lock-screen.md` 用文件名前缀而非命名规则。
- **issue 同号**：本地 `245~254` 与上游 `245~301` 同号不同题；本地 `168~176` 与上游同号。
- **已有先例**：本地已把上游早期 `168~176` 归档到 `issues/upstream-yeshimei/`（7 篇），命名空间隔离在本仓库已经跑通。

## 决策

1. **上游 ADR 一律进 `docs/adr/upstream-yeshimei/`**，**保留原文件名**——包括重号（两个 `0110`）与不规范命名（`ADR-0124-...`）。不重编、不合并、不改名。
2. **上游 issue 沿用 `issues/upstream-yeshimei/`**（既有先例），同样保留原文件名。
3. **本地编号从 `0117` 起连续发放**，不受上游影响；本地文件继续平铺在 `docs/adr/`。
4. **引用格式**：正文提到上游决策一律写「上游 ADR-XXXX」/「上游 issue NNN」；裸写「ADR-XXXX」默认指本地。跨线内容必须带「上游」二字。

## 理由与边界

- **为什么不重编上游编号**：重编要改正文里所有交叉引用，且上游未来新增号又会撞——重编是持续成本，隔离是一次性成本。
- **为什么不让上游改名**：本仓库对上游无写权限，且上游的编号策略不受我们控制。
- **边界**：`upstream-yeshimei/` 是**只读归档**——本地不修改归档文档内容；本地对上游决策的评估与反驳写在本地 ADR / ticket 正文里。
- **不做的事**：不把双边**同名同内容**的 ADR（共同祖先期产物，编号一致、内容一致）复制归档；只归档上游独有及内容分叉的。
