# 人物深度设计模板与速查表

> 配合 SKILL.md 十步门链使用。条目均为默认规格，可在本书范围内调整。

## 〇、层级口径统一（主角+最重要反派单独成层）

主角与最重要反派**从核心层提出、独立成 L1 层**（用 G3.1＝主角深度 与 G3.2＝最重要反派深度 两套标准，不用核心人物标准设计）；L2「核心人物层」只含其余核心人物。五层结构与 G3.0 原文四层级代号档位的映射：

| 五层结构（设计推进分层） | G3.0 原文四层（代号档位） | 代号 |
|---|---|---|
| L1 主角 + 最重要反派（成对，独立层） | 核心层中的主角/反派单列 | C01 / C02 |
| L2 核心人物（支持侧 + 对抗侧） | 核心层余下人物 | C03、C05… / C04、C06… |
| L3 重要配角（支持侧 + 对抗侧） | 重要层 | M01~ / M10~ |
| L4 功能性配角（支持侧 + 对抗侧） | 功能层 | F01~ / F10~ |
| L5 背景人物 | 背景层 | B{卷}-NN |

即：**五层 = 主角/反派(L1) + 核心人物(L2) + 重要(M) + 功能(F) + 背景(B)**。「四层」指 G3.0 的代号档位（C/M/F/B），其中 C 档被拆成 L1（主角+最重要反派）与 L2（其余核心）两层——主角/反派因深度标准更高而单独成层，代号仍沿用 C01/C02，不改变其在 C 档的位置但**设计标准独立**；本 skill 叙述用「五层结构」。

## 一、初始/最终状态快照维度清单（对照用，选 ≥6 维）

1. 外部生活（地位/资源/日常）
2. 认知框架（相信什么/如何看待世界）
3. 欲望与压抑（要什么/压着什么不要）
4. 补偿策略（用什么填内心缺口）
5. 关系模式（对人的一贯姿势）
6. 触发点（什么刺激会失态）
7. 潜在能量（未被使用的天赋/破坏力）
8. 对外呈现（人设面具）
9. 象征物（随身物件/习惯动作及其含义）

反派版替换：维度 5 →「对权力/亲近/威胁/重复剧本的态度」；维度 7 →「隐藏的脆弱或温情」。

## 二、弧线类型速查

| 类别 | 子型 | 一句话 |
|---|---|---|
| 正面 | 成长/顿悟 | 克服缺陷变成更好的人 |
| 负面 | 堕落/幻灭/腐败 | 被缺陷吞噬 |
| 静态 | 平弧考验 | 不变的人改变周围 |
| 特殊 | 螺旋/顿悟失败 | 绕圈式变化 |

弧线驱动根源 = 未被满足的需求 ＋ 已被剥夺的东西（对应马斯洛层次标注）。

## 三、性格咬合矩阵八型

镜像冲突 / 互补 / 相互利用 / 协同 / 潜在冲突 / 追逃 / 同途殊归 / 价值对立。
分布要求：冲突类（镜像冲突/潜在冲突/追逃/价值对立）合计占关键关系 40-65%；主角至少与反派、与一名核心支持者各有明确咬合。

## 四、缺陷-创伤因果链模板

```
创伤事件（具体场景，非标签）
  → 错误认知（从此我相信……）
  → 性格缺陷（因此我总是……）
  → 防御机制（我用……保护自己）
  → 代价（这让我失去……）
```
配套：代表性词汇四组（核心消极/辅助消极/核心积极/辅助积极），须覆盖道德、成就、互动、身份四个属性域各一词。

## 五、内部困境轨迹

- 困境类型四选一：救赎 / 醒悟 / 蜕变 / 承受；
- 三阶段：困境成形 → 矛盾激化 → 解决或付出代价；
- **穿透性时刻**：外界一句话/一件事直接击穿错误认知的瞬间（全书 1-3 次，标章节）；
- **错误出口**：主角在困境中曾选择的错误解法（它让后期代价成立）；
- 关键选择级联：每个重大选择引出的下一重困境，串成链。

## 六、变化事件两类

- **T 事件**（类型变化）：身份/立场/能力的质变，如晋升、觉醒、黑化；
- **R 事件**（关系变化）：两人关系的质变，须双方档案各记一笔。
每条事件记三要素：触发原因 → 可见表现 → 状态前后对比。主角 T 事件 ≥4 个；主角-反派关系线中间状态 ≥4 个。

## 七、语言特征卡（并入角色档案，配合 story-style-spec 使用）

语言特征卡以 `story-style-spec` 步骤 5 的十要素为准（七要素 + 语速/节奏、沉默模式、爱的语言体现）；本表不重复定义。

## 八、一致性自检十项（单人物收尾）

① 心结-恐惧-弱点三角自洽；② 缺陷与创伤因果成立；③ 弧线五阶段覆盖所有 T/R 事件；④ 快照前后对照有可见差异；⑤ 语言特征与内核一致；⑥ 情节驱动锚点均落在卷纲已有章节；⑦ 与主角咬合类型兑现；⑧ 独特性红线无违反；⑨ 反派附加：胜利剧本合理且非工具人；⑩ 遗留冲突标记 🔴🟡🟢 并给出处理建议。

## 九、动态启发兜底

任何设计点卡壳：连续 3 轮无满意方案 → 采用当前最优占位值，标注 `[占位待复核]` 继续推进，不空转；用户可随时回头改。

## 十、判断显式化协议（全局强制执行）

任何**归类、层级判定、类型选择、功能匹配**等需要按既定标准做判断的环节，一律三段式输出，不得直接给结论：

```
标准条目 → 本案例匹配情况 → 结论
```

- **标准条目**：引用判定依据本身（层级分级的叙事权重标准、咬合矩阵定义、性格类型特征、功能匹配规则等）；
- **本案例匹配情况**：逐条说明当前人物/关系的对应与偏离，用户据此可直接定位偏差，无需猜测 AI 的归类逻辑；
- **结论**：仅在前两段齐备后给出（归属/层级/类型/匹配成立与否）。
- **适用范围**：第一步层级分级与支持/对抗归类、咬合类型分配、性格词典匹配（见十一）、功能层叙事任务匹配、第五步同型破格告警、第六步交叉核查的每一条判定。
- **来源**：G3.0 输出约束 #6 原文（「标准条目 → 本案例匹配情况 → 结论」），贯穿 G3.0-G3.9 全部 10 份文件。

## 十一、性格类型锚点状态机与性格词典交互（G3.0 第四步）

### 1. 锚点状态机（`personality_type_anchor.status`）

| status | 含义 | 后续处理 |
|---|---|---|
| `confirmed` | G3.0 已确认类型 | 单人物设计（G3.1 第 4.0 步 / G3.2 第 3.0 步 / G3.3-G3.4 第 5.1 步 / G3.5-G3.6 第 5.1 步）**直接引用、跳过询问**；草案开头标注「基于 G3.0 第四步已确认的性格类型锚点：[系统-类型]」；仅用户主动要求修改才重开交互 |
| `pending` | 待本次确认 | 询问用户提供参考（九型/MBTI/本能亚型/对标角色/性格关键词等），或 AI 基于 G3.0 速写变量＋功能定位推断；确认后回写 confirmed |
| `deferred` | 暂缓绑定 | 同上走询问/AI 推断；用户坚持跳过则基于速写变量推进，锚点留待后续补充 |

状态字段与数值必须同记于 `_人物框架.md`（G3.0 整体核查含「性格类型锚点的状态是否正确记录」一项）。

### 2. 性格词典交互协议（G3.0 阶段二/阶段三）

1. **强制询问**（阶段二）：草图展示后即询问，四个出口——发送词典 / 自行指定 / 跳过 / 混合模式。
2. **提取词典**：用户可一次发多个系统；每系统独立提取核心特征（基本恐惧/基本欲望/行为倾向/防御机制/压力与安全状态行为变化）。
3. **逐人物匹配**（阶段三）：按四维比对——核心恐惧↔基本恐惧、核心欲望↔基本欲望、核心信念↔认知模式、行为模式↔典型行为倾向。
4. **每系统最多推荐一个最佳匹配**（标注系统前缀区分），输出主推荐＋次选＋匹配依据；**无合适匹配 → 标注「无合适匹配」并保留原草图，不强制匹配**。
5. **变量对齐**：保留推导来源不变，把自然语言变量对齐词典术语（如「害怕被抛弃」→「害怕失去支持和指导（九型 6 号基本恐惧）」；「攻击型」→「对抗型（九型 8 号核心防御策略）」）。
6. **确认循环**：全部采用主推荐 / 改用次选 / 指定具体类型 / 展开逐条对照 / 没想法由 AI 定；卡壳 3 轮按第九章动态启发兜底。

## 十二、关键节点心理状态详表模板（T/R 事件节点 · 14 字段）

> 配合 SKILL 第二步第 ⑤ 步使用。核心层共用（主角 G3.1 第 5.6 步 / 最重要反派 G3.2 第 4.6 步）；重要层用简化版（G3.5 6.6 / G3.6 6.6，字段压缩为事件编号/类型/触发章节/锚点·外在目标/内在动机/障碍/克服-未克服/变化后的行为改变）。

每个事件节点一行，14 字段（顺序即表头）：

| # | 字段 | 要求 |
|---|---|---|
| 1 | 事件编号 | T/R 编号与 G3.0 变化事件总表一致 |
| 2 | 类型 | 类型变化 T / 关系变化 R |
| 3 | 触发章节 | 与 G3.0 总表锁定的触发章节一致 |
| 4 | 锚点·外在目标 | 该事件中的外在目标 |
| 5 | 内在动机 | 驱动该目标的内在需求 |
| 6 | 外在冲突 | 目标遭遇的外部对抗 |
| 7 | 外在原因 | 冲突的外部来源/阻碍 |
| 8 | 内在冲突的具体表现 | 心理冲突的可见表现 |
| 9 | 障碍 | **内外叠加后发生的具体事件，可被写进章节** |
| 10 | 克服/未克服 | 是/否 |
| 11 | 若克服 | 积极特质的作用＋外部帮助 |
| 12 | 若未克服 | 失败原因＋人物选择＋新后果 |
| 13 | 防御机制 | 与缺陷-创伤因果链（见第四章）一致 |
| 14 | 变化后的行为改变 | 事件之后行为/应对的变化 |

使用规则：

- **覆盖完整性**：必须覆盖 G3.0 总表中该人物**所有** T/R 事件；遗漏将在弧线覆盖性核查与整体校验中被标记为不一致。
- **一致性**：同一阶段内事件汇总后的心理状态须与五阶段宏观描述吻合；触发章节逐条与 G3.0 比对；触发章节偏差的处理：调整弧线阶段划分，或在该行增加额外心理铺垫说明为何此阶段已有能力发生该变化。
- **T→R 连锁**：由 T 触发的 R（`triggered_by_type_change_event`）必须在表中体现因果关系。
- **C02 专属要求**：T 事件 ≥ 4（首次动摇→第 2 中间节点→第 3 中间节点→彻底转变）；C01-C02 关系线 R 中间状态 4-5 个（如首次困惑→短暂共鸣→信念裂痕→互相尊重）。

## 十三、幽默增强模块（可选 · 含 HT-01~15 技巧库骨架）

> 默认非标配：先判适配，不适合即跳过。核心层走完整流程（G3.1 十-D / G3.2 6.9）；重要层走简化二步（G3.5 8.7 / G3.6 8.8）。

### 1. 适配性检查（第〇步，强制执行）

| 检查项 | 判什么 | 结论 |
|---|---|---|
| 性格适配 | 性格是否天然容纳幽默；不直接容纳时存在何种变体形式（≥30 字） | ✅ 适合 / ⚠️ 需调整形式 / ❌ 不适合 |
| 功能适配 | 叙事功能是否允许幽默（增强共情/从容感，而非削弱严肃性/压迫感；≥30 字） | ✅ 适合 / ⚠️ 仅限特定场景 / ❌ 不适合 |
| 弧线适配 | 幽默演变是否与弧线方向一致（如防御性自嘲→真正松弛；堕落弧从轻松从容→苦涩反讽→消失） | ✅ 一致 / ⚠️ 需调整演变方向 |
| 综合结论 | ✅ 设计增强 / ⚠️ 严格限定形式与频率 / ❌ 跳过模块 | — |
| 若适合或需调整 | 形式＋频率范围（F1 极低~F5 高）＋场景限制 | — |

**跳过机制**：综合结论 ❌ 时输出「幽默模块跳过＋具体原因＋替代处理」（该人物语言风格、行为模式等维度已足够塑造独特性），**不再进入词典与选技巧步骤**，记录 `humor_applicability = 不适用`。

### 2. 幽默技巧词典交互

- **强制询问**（结论 ✅/⚠️ 时）：素材请求脚本——技巧词典（编号-名称-说明对照表）/ 风格关键词（冷幽默、黑色幽默、自嘲、荒诞、尴尬、文字游戏、反差等）/ 对标角色 / 禁用方向 / 频率偏好（F1-F5）。
- **筛选规则**：用户提供词典 → AI **只能从用户词典中筛选**，不得混入技巧库（除非库中已含相同技巧）；重叠时编号以用户词典为准；未提供 → 从 HT-01~15 库筛选。
- **推荐数量**：2-4 个，上限 `max(2, floor(2 + sqrt(总字数万字 / 20)))`；每项附咬合理由（≥20 字）＋具体场景示例，不能只给名称。
- **确认循环**：确认 / 替换（提供编号和名称）/ 增删 / 没想法换一批；卡壳 3 轮按第九章动态启发兜底。
- **G2.1 联动**：若存在 `humor_theme_mapping`，优先提取苦笑倾向（苦笑转化层次 L1-L5，专属于苦笑分型）、核心技巧、与心结关联、演变起点与终点；与用户确认结果冲突时以用户确认为准并标注「用户偏好优先于 G2.1 映射」。

### 3. 幽默风格草案字段

核心幽默技巧选择（用户确认的编号及名称）／苦笑倾向（苦笑转化层次 L1-L5）／演变方向（与弧线方向一致）／禁用技巧（与性格冲突或用户明确禁用）／频率等级（F1-F5）／典型幽默场景（1-2 类）；多卷故事加分卷演变表；收尾做性格-幽默匹配检查（技巧↔人格类型、苦笑↔心结、禁用↔性格冲突、演变↔弧线）。

## 十四、G3.0 全局工件速查（配合 SKILL 第一步第 6 条）

### 1. 变化事件总表（G3.0 第八步）

四类事件全部锁定**触发章节＋触发事件描述＋连锁影响**：

- **S-T（初始类型锚定）**：锚定事件须早于该人物第一个 T 事件，且是具体场景（示例：「第 15-20 章，C02 通过 M19 标记首次注意到 C01——『又一个想靠特殊突破规则的人』」），禁止「C02 一开始是观察者」式无章节描述。
- **S-R（初始关系锚定）**：锚定章节须早于该关系第一个 R 事件，同为具体场景。
- **T（类型变化）**：触发事件必须击中核心恐惧或挑战核心信念；触发章节与关键故事节点大致对齐（首次动摇≈中间点、彻底转变≈关口二/高潮）；连锁影响列必填（触发多条 R 必须全标）。
- **R（关系变化）**：标注变化前后关系、触发章节与事件、是否由某 T 触发（`triggered_by_type_change_event`）。

**全局分布概览（8.5）** 检查七维并落概览：① 关键节点密度梯度（四类事件合并统计；中间点/关口二密度最高或次高；无零事件节点；S 锚定不晚于首次出场）；② T/R 交替节奏（前后半段均衡、避免连续 3+ 同型）；③ 状态链完整性（有 T 必有 S-T、有 R 必有 S-R、无因果倒置）；④ 连锁间隔（同链条事件间隔通常 1-3 章）；⑤ 人物线交错（无人物线连续超总章数 30% 无状态事件）；⑥ **静默期**（连续超总章数 10% 无状态事件 → 判断合理或建议推进；连续 3 章以上每章有事件 → 设置缓冲章节）；⑦ 变化模式独特性（6 种趋同检查：理解节点扎堆中间点、盟友全走「分歧→修复」、T 全挤中间点-关口二、R 全因真相揭露、只有对抗方转变、分布过于均匀）；⚠️ 项必须给具体差异化建议。概览含按关键节点/人物线/按卷分布与静默期标注。

### 2. 出场密度等级公式（第九步 9.2）与单章峰值

| 人物等级 | 出场章节数 | 说明 |
|---|---|---|
| 核心-主角 C01 | ≈ 总章数 × 0.7-0.9 | 几乎章章在场，允许部分章节淡出 |
| 核心-最重要反派 C02 | ≈ 总章数 × 0.35-0.55 | 准主角级叙事权重 |
| 核心-其他核心反派 | ≈ 总章数 × 0.3-0.5 | 关键节点和重要场景持续存在 |
| 核心-核心盟友 | ≈ 总章数 × 0.25-0.45 | 略低于核心反派，高于重要配角 |
| 重要配角 M | ≈ 总章数 × 0.1-0.2，至少 3 章 | 阶段性出场，围绕功能节点分布 |
| 功能层 F | 1-3 章 | 点状出场，任务完成即退场 |
| 背景层 B | 1 章（可跨多章作为背景） | 随场景出场，不需单独规划 |

**单章峰值**（9.8.1 核查）：任一章节同时出场的有名字人物（核心＋重要＋功能）**不宜超过 12 人**（硬上限）；G3.9 逐章评估：正常 2-6、偏高 7-8 需关注、⚠️ 9+ 建议分散、⚠️ 0-1（非静默期关键章节）建议增加出场；峰值 >8 且含多个首次见面/关系转折事件时对话场景可能过挤。调整优先级：先挪功能配角 → 再拆场景 → 核心/重要节点尽量不动（动则同步回写第八步触发章节）。

### 3. 入场卷次标注（活跃卷次）

每角色标注活跃卷次「卷X-卷Y」（如「卷1-5」）或「卷X」（仅单卷出场）；核心层与重要层**必标**，重要层不得用「待定」；供卷级分布核查与后续出场调度。各卷均衡检查：每章平均新人物引入 ≤1.5（卷一建置期可略高至 2.0）；S-T/S-R 锚定不晚于首次出场。

### 4. 独特性红线生成物（第十步 10.9）

核心冲突＋主题金句 → 生成 3-5 条红线：每条以「禁止/必须」开头、直接关联核心冲突或主题金句、指向具体约束对象、附约束说明；编号 U-01~。示例：U-01 禁出现两个以上「对抗→理解→尊重」三段式；U-02 禁支持力量类型集中在「伙伴/信息提供者」；U-03 禁类型变化全部集中在中间点附近；U-04 自定义类型数量下限；U-05 C02 关系演变线 4-5 个中间节点。8.5.7 发现的同质化风险必须转化为红线。使用规则：单人物设计第二步展示红线并标注「以下设计必须遵守 G3.0 独特性红线」，校验步骤逐条核对。
