# story-character-lab：人物实验室（五层 × 六型阵营迁移 × G3.0→G3.9）

## 定位与守门（我在流程中的位置）

- **位置**：全书流程第 4 阶段（约束清单门之后、大纲之前），见 `story-stepwise/references/book-roadmap.md` 阶段 4。
- **上一步产物**：`大纲/_约束清单.md` + `设定/_开书.json`（四锚定字段）+ `设定/角色/` 现有档案。
- **本 skill 产出**：`设定/角色/_人物框架.md`（五层结构 + faction_arc 状态机，仅作**索引目录**）+ **逐人独立人物卡文件** + `设定/关系.md` 情感关系小节。
- **下一步路由**：说「写大纲/体量总览」→ `story-long-write` Phase 3。
- **人物文件命名规范（强制执行）**：人物卡文件名 = **`{类型编码}_{人物名}.md`**（下划线分隔）。类型编码沿用 G3.0 四档 `C`核心 / `M`重要 / `F`功能 / `B`背景 + 两位序号，如 `C01_林婉秋.md`、`C02_沈墨白.md`、`M05_周管家.md`、`F03_小贩.md`。编码由 G3.0 第五步「人物代号分配」产出；名字未定稿时先写 `C01_未命名.md`，定名后重命名。
- **逐人必成独立卡（强制执行）**：G3.0 框架定的**每一层每一个人**，都必须在 `设定/角色/` 下有一张独立人物卡文件（深度设计也写进该人名卡，不另开文件）；`_人物框架.md` 只是索引/速查，**不得替代任何人物卡**。五层全部逐人成卡，**唯一例外：背景层（L5/G3.8）按「组」成卡**（如 `B_龙套组.md`，组内列成员清单），不逐个建档。禁止「只记进框架文件、不建独立卡」，尤其重要配角/功能配角不得遗漏。
- 前置：主题与核心冲突已确认、体量已定、**四锚定门已锚定（开书 OB-3~3.7）**。缺失时提示先回 `story-openbook` 补齐，不凭空设计。
- **前置·篇幅字段**：进入 G3.0 前确认 `设定/_开书.json` 的 `length_params`（total_chapters / words_per_chapter / total_words / volume_tier）四字段非空——G3.0 各层人物数量公式（重要层 `max(2, floor(总章节数/15)+…)`、功能层 `ceil(总章节数/20)`、出场密度 `总章数×0.1-0.2`、单章峰值 ≤12）均消费 `length_params`；缺失时先回 `story-openbook` OB-1 补「篇幅三连」，再继续人物设计。
- 确认节奏遵循逐步确认模式：**每完成一个步骤停下展示要点等确认，再进下一步**。卡壳/启发轮换/3 轮占位/素材请求（性格词典）的通用规则见 `story-stepwise/references/interactive-protocol.md`。
- **判断显式化协议（强制执行）**：凡归类、层级判定、类型选择、功能匹配等按标准判定的环节，必须逐条输出「标准条目 → 本案例匹配情况 → 结论」三段后再给结论（源自 G3.0 输出约束 #6；三段式说明见 reference 第十节）。
- 深度模板与速查表见 [references/depth-modules.md](references/depth-modules.md)，进入各步前按需读取。
- **源 A 商业方法注入**：原版 `character-design-methods.md`/`character-basics.md` 方法（三层标签反差/反派四档/动机链 CICR/代入感/主角红线/配角功能化等）作为各步**设计内容增强**注入，精炼速查见 [references/commercial-character-methods.md](references/commercial-character-methods.md)，注入点映射见 depth-modules 〇-1。G3 十步门链仍是主骨架，源 A 只注入不替代。

## 执行总流程（运行时唯一依据 · 两阶段 + 收尾）

> 本 skill 的人物设计永远是「**先按篇幅定框架（人数 + 两侧 + 阵营迁移 + 反派四档 + 关系）→ 再逐人按层标准设计 → 最后全人物核查**」三段，不跳步、不颠倒。此节为权威总图；细节落在下方「五层人物结构」与「十步门链」，二者不得与本节冲突。

### 第一阶段 · 框架搭建（G3.0，全书只做一次）

1. **按篇幅定各层人数**（输入 = `设定/_开书.json` 的 `length_params`，各层数量公式消费它）：
   - L1：主角 1 ＋ 最重要反派 1（固定，不按公式）
   - L2 核心层：主角方核心支持力量 N ＋ 对抗侧核心人物 N
   - L3 重要层：主角方重要配角 N ＋ 对抗侧重要配角 N
   - L4 功能层：主角侧功能配角 N ＋ 对抗侧功能配角 N
   - L5 背景层：背景人物 N 组（随场景批量）
2. **六型阵营迁移登记**（`faction_arc`，每笔标 `start → end` 与落点归属；无迁移标「稳定」）：
   - 主角方→反派方（背叛/黑化）＝ 落点**算对抗侧**
   - 反派方→主角方（归化/洗白）＝ 落点**算支持侧**
   - 主角方→中立方（淡出）＝ 落点**算中立**（既非支持也非对抗）
   - 反派方→中立方（脱离）＝ 落点**算中立**（**不是**主角支持力量）
   - 中立方→主角方（吸纳）＝ 落点**算支持侧**
   - 中立方→反派方（卷入）＝ 落点**算对抗侧**
   - ⚠️ **中立是独立第三态**：任何「→中立」都不等于倒戈到主角，只算中立。
3. **反派四档标注**（`villain_tier`，**仅对抗侧**，支持侧不设）：小反派 / 中等反派 / 大弧Boss / 最终Boss。
4. 性格咬合矩阵预排（八型）→ 5. 性格词典交互与锚点状态机 → 6. 全局工件（变化事件总表 / 出场密度 / 入场卷次 / 独特性红线）。
7. **关系网络初设 ＋ 情感关系门**（衔接开书 OB-3.7；逐对核心关系 + 感情线基调兑现，见下文「情感关系门」）。

### 第二阶段 · 逐人深度设计（G3.1→G3.8，按「层」用对应标准，对抗侧再按「档」强化）

| 顺序 | 设计对象 | 标准文件 | 对抗侧反派档 |
|---|---|---|---|
| 1 | 主角 | G3.1 | — |
| 2 | 最重要反派 | G3.2 | 最终Boss |
| 3 | 核心·支持力量 | G3.3 | — |
| 4 | 核心·对抗力量 | G3.4 | 大弧Boss |
| 5 | 重要·支持力量 | G3.5 | — |
| 6 | 重要·对抗力量 | G3.6 | 中等反派 |
| 7 | 功能配角（两侧分列） | G3.7 | 对抗侧＝小反派 |
| 8 | 背景人物（批量） | G3.8 | — |

> 「层」看叙事权重（决定用哪份设计标准），「档」看冲突规模（决定对抗侧角色用哪级原版反派标准）；二者正交、都要标。

### 第三阶段 · 收尾核查（G3.9）

全人物交叉核查 ＋ `faction_arc` 迁移链全局核对（无悬空、迁移三事件齐全）＋ `villain_tier` 四档核对（篇幅与档位匹配、无降智送赢）＋ 商业维健康度（原版 20+ 项）。

## 五层人物结构（两侧二分 + 六型阵营迁移）

> **文件号 → 层/侧 唯一对照（运行时以此为准，禁止省略为斜杠简写）**：
> - G3.1＝L1 主角（支持侧本身）；G3.2＝L1 最重要反派（对抗侧·最终Boss）
> - G3.3＝L2 核心人物·**支持力量**；G3.4＝L2 核心人物·**对抗力量**
> - G3.5＝L3 重要配角·**支持力量**；G3.6＝L3 重要配角·**对抗力量**
> - G3.7＝L4 功能配角（一份文件，卡内分两侧）；G3.8＝L5 背景人物（可按侧标色）
> - 每层仍完整分「支持侧/对抗侧」两半；「G3.3/G3.4」这种写法**一律视为「G3.3（核心·支持）＋G3.4（核心·对抗）」两个文件**，绝不是把两层合并。

| 层 | 组成（支持侧 + 对抗侧） | 设计提示词文件 |
|---|---|---|
| L1 主角/最重要反派 | 主角 + 最重要反派（成对设计） | G3.1（主角）+ G3.2（最重要反派） |
| L2 核心人物 | 主角支持力量·核心 + 反派支持力量·核心 | G3.3（核心·支持）+ G3.4（核心·对抗） |
| L3 重要配角 | 主角支持力量·重要配角 + 反派支持力量·重要配角 | G3.5（重要·支持）+ G3.6（重要·对抗） |
| L4 功能性配角 | 主角侧功能配角 + 反派侧功能配角 | G3.7（功能·两侧） |
| L5 背景人物 | 背景人物（随场景批量，可按所属侧标色） | G3.8（背景·可按侧标色） |
| 收尾 | 全人物整体核查与交叉验证 | G3.9 |

> **层级口径（主角+最重要反派单独成层）**：主角与最重要反派**从核心层提出、独立为 L1 层**（用 G3.1（主角深度）与 G3.2（反派深度）的更深标准，而非核心人物标准），L2「核心人物层」只含**其余**核心人物——避免主角/反派被按核心人物标准降格设计。对照 G3.0 原文四层级代号档位（核心 C / 重要 M / 功能 F / 背景 B）：L1 对应于 C 档中的主角+最重要反派（C01/C02）单列，L2 对应 C 档余下核心人物，L3=M、L4=F、L5=B，代号仍沿用 C/M/F/B（映射见 depth-modules 〇节）。

**阵营迁移全景（六型，任意层任意侧适用）**：支持→对抗（背叛/黑化）＋ 对抗→支持（归化/洗白）＋ 支持→中立（淡出）＋ 对抗→中立（脱离）＋ 中立→支持（吸纳）＋ 中立→对抗（卷入）。三阵营状态机：`faction_arc = { start ∈ {支持,对抗,中立}, end ∈ {支持,对抗,中立}, triggers[3]（动摇→关键事件→立场转变）, chapter }`；G3.0 第七步登记占位（可标「稳定、无迁移」）→ G3.3（核心·支持）＋G3.4（核心·对抗）、G3.5（重要·支持）＋G3.6（重要·对抗）、G3.7（功能）兑现 → G3.9 全局核对。

- **操作标准**：G3.4 背叛者三事件链 / 背叛条件 / 镜像对照；**兑现该侧 faction_arc（支持→对抗、中立→对抗）**。**子步骤文件**：`小说设置提示词/G3.4 核心人物-对抗力量深度设计/`（00 外壳与总览 → 01 锁定对象 → 02 数据摘要 → 03 重置声明 → 04 变化事件梳理 → 05 性格内核 → 06 弧线与心理动因 → 07 外在表现 → 08 深度补充 → 09 情节驱动锚点 → 10 统一梳理 → 11 单人内部校验 → 12 归档确认 → 13 跨人物整体校验 → 99 输出 JSON），逐文件确认。
- **源 A 注入**：标注 `villain_tier = 大弧Boss`（按篇幅/冲突规模判定）；用反派四要素做模块级校验。
- **产物**：逐人成卡 `设定/角色/C0X_{人物名}.md`（背叛者三事件链 + villain_tier=大弧Boss）；本侧全部核心·对抗人物都需有独立卡。

### G3.5（重要·支持）/ G3.6（重要·对抗）→ 「设计重要配角（支持侧/对抗侧）」
- **操作标准**：G3.5（重要·支持）与 G3.6（重要·对抗）三阶段弧线（起因-转折-落定）/ 聚焦 1-2 困境 / 3-4 维简化快照 / 出场配额 10-20%；**兑现 faction_arc**（支持→中立、对抗→中立等中立迁移通常落于此层）。**子步骤文件**：支持侧 `小说设置提示词/G3.5 重要配角-支持力量深度设计/`、对抗侧 `小说设置提示词/G3.6 重要配角-对抗力量深度设计/`（各均为 00 外壳与总览 → 01 锁定对象 → 02 数据摘要 → 03 重置声明 → 04 变化事件梳理(简化) → 05 性格内核(简化) → 06 三阶段弧线 → 07 外在表现(精简) → 08 深度补充(简化) → 09 情节驱动锚点 → 10 统一梳理 → 11 单人内部校验 → 12 归档确认 → 99 输出 JSON），逐文件确认。
- **源 A 注入**：配角执念设定法、人设关系四阶段（相遇/相识/相知/相恋亲密度刻度）、出场频率 3-5 章、记忆点；对抗侧标注 `villain_tier = 中等反派`。
- **产物**：逐人成卡 `设定/角色/M0X_{人物名}.md`（三阶段弧线 + 3-4 维简化快照 + 出场配额）；本层全部重要配角（支持侧+对抗侧）都需有独立卡，不得并卡、不得只记进框架文件。

### G3.7 功能性配角卡片 → 「设计功能配角」
- **操作标准**：G3.7 四要素 + 边界声明 + 变化事件清单；**两侧分列（主角侧/反派侧）**。**提示词为单文件**：`小说设置提示词/G3.7 功能性配角卡片设计.md`（未拆子目录；本层为卡片级，单文件内按「个别人物→确认→下一个」推进即可，但仍逐人确认）。
- **源 A 注入（把卡片做厚）**：人设反差六维度法（选 1-2 维贴标签）、配角功能化核心原则（能力为主角所用）、期待枢纽（人物扣）；对抗侧标注 `villain_tier = 小反派`。
- **产物**：逐人成卡 `设定/角色/F0X_{人物名}.md`（四要素 + 边界声明 + 变化事件清单）；功能性配角逐个成卡，不得合并。

### G3.8 背景人物批量 → 「批量设计背景人物」
- **操作标准**：G3.8 刻板+破格公式 / 满 3 告警 / 场景绑定 / 跨层辨识度；可按所属侧标色。**提示词为单文件**：`小说设置提示词/G3.8 背景人物批量设计.md`（未拆子目录；本层为批量级，按批次展示→确认推进）。
- **源 A 注入**：群像写作法（出场有功能无水分）、角色池编织法（以角色带角色）。
- **产物**：按组成卡 `设定/角色/B_{组名}.md`（戏份过多或跨多卷的背景人物可升档单独立卡，否则按组列成员清单，不逐个建档）。

### G3.9 全人物交叉核查 → 「交叉核查」
- **操作标准**：G3.9 六项交叉核查 + 独特性红线逐条核对 + 时间线总检 + **faction_arc 迁移链全局核对（无悬空、迁移三事件齐全）** + **villain_tier 四档全局核对（对抗侧角色均已标注、篇幅与档位匹配、无降智送赢）** + **商业维健康度核查（原版 20+ 项：主角/配角/反派/商业红线，见 commercial-character-methods.md 第七节）** + **人物卡完整性核对（新增·强制）**。**子步骤文件**：`小说设置提示词/G3.9 全人物整体核查与交叉验证/`（00 外壳与总览 → 01 重置声明 → 02 跨层级关系变化交叉验证 → 03 类型变化连锁验证 → 04 出场调度总检 → 05 变化事件时间线总检 → 06 全故事独特性评估 → 07 弧线情节咬合全局核查 → 08 修订建议清单 → 09 交互确认 → 99 输出 JSON），逐文件确认。
- **人物卡完整性核对（强制，缺卡=未完成）**：对照 G3.0「人物框架」定下的**全部人物清单**（按层：L1 主角+反派 → L2 核心 → L3 重要 → L4 功能 → L5 背景组），逐人核对 `设定/角色/` 是否已有对应的独立人物卡文件（命名规范 `{编码}_{名}.md`，背景层按 `B_{组名}.md`）。**任何一个人（或组）缺卡，或文件名编码与 G3.0 代号分配不一致，本步判定「人物设计未完成」，回对应 G3.x 步补产，不得交棒大纲。** 完卡后输出一张「人物卡完整性清单」（编码·名字·文件名·对应 G3.x），供用户最终确认。
- **产物**：修订清单 + 人物卡完整性清单 → 交棒约束清单门/大纲。

## 增量补人与改人模式（大纲期/正文期中途调用）

> **适用**：卷纲/粗纲欠账回补、细纲设定补全路由（`story-outline-detail` 步骤 8）、场景卡欠账点经细纲回补、正文期剧情确需新增或修改人物。触发词：「增量补人」「细纲补人」「给XX补深度人设」「改XX人设」。**前提：G3.0 框架已存在**（`设定/角色/_人物框架.md` 与 C/M/F/B 代号体系已定）；框架不存在时走上方完整 G3.0→G3.9 流程，不使用本模式。

### A. 增量补人（新人物）
1. **来源合法性校验**：新人物须来自被授权的进入位置——卷纲/粗纲欠账点回补、细纲步骤 8「非主线会复用配角」、场景卡欠账点经细纲回补。主线级新人物未经卷纲/粗纲确认，不得在本模式直接造。
2. **层级判定（判断显式化三段式）**：按叙事权重定层——中途补人通常落 L2-L4；L1（主角/最重要反派）级新增须用户显式确认并提示对全书结构的影响；一次性路人/无戏份配角不补，归 L5 背景组。对抗侧再按冲突规模定 `villain_tier` 四档。逐条输出「标准条目 → 本案例匹配情况 → 结论」。
3. **代号分配**：沿用 G3.0 四档 C/M/F/B 编码体系，取该层未用最小序号；L5 背景并入既有组卡或新建 `B_{组名}.md`。
4. **按层标准设计**：按上方「第二阶段」表锁定对应 G3.x 步骤与 `小说设置提示词/` 子步骤文件，**逐子步骤确认**；深度要求与全书设计期完全一致，不得中途降档（防跨级套用防线同原规则）。
5. **框架登记**：更新 `_人物框架.md`（索引行 + `faction_arc` 登记 + 出场密度重算，超出密度预算时标注并请用户取舍）；回写关系涉及者人物卡的关系小节；涉及情感关系时更新 `设定/关系.md`。
6. **局部核查（G3.9 相关子集）**：跨层级关系变化交叉验证、出场调度、变化事件时间线、人物卡完整性清单增量核对；无需全书重跑 G3.9。
7. **产物与回交**：`设定/角色/{编码}_{人物名}.md` + 框架更新；明确报告「已可回到触发步骤」（细纲继续本批补纲 / 场景卡重跑该章），不停留在本 skill。

### B. 改人（已有人物修改）
1. **跨产物修订门禁前置**：已确认人物卡属设定产物，先按 AGENTS.md 跨产物修订门禁做只读影响分析（生成 `追踪/修改影响/active.json`），圈定受影响的粗纲/细纲/场景卡/正文范围，再动卡。
2. **修改范围判定**：只重设计受影响模块（如外在表现/关系小节/情节驱动锚点）；伤及性格内核、弧线锚点或深度模块（九维快照/胜利剧本/三事件链）时，按该层标准重做对应子步骤并**逐子步骤确认**，不整卡静默重写。
3. **同步回写**：`_人物框架.md`、关系涉及者卡片、`设定/关系.md` 同步更新；修改记录登记 `_meta.modifications`。
4. **局部核查与复核**：同 A6；完成后按跨产物修订门禁 `phase=verify` 复核；受影响的细纲/场景卡按各自「过期重跑」规则处理——本 skill 只报告影响清单，不代改大纲产物。

## 层级标准防线

| 层 | 深度标准 | 备注 |
|---|---|---|
| L1 | 十步深度 + 14 字段心理详表（G3.1 主角 / G3.2 最重要反派） | 主角 T≥4、主角-反派 R 中间态 ≥4；反派=最终Boss 档 |
| L2 | 归化/背叛深度模块（G3.3 核心·支持 / G3.4 核心·对抗） | 三事件链落到章节；对抗侧=大弧Boss 档 |
| L3 | 三阶段弧线 + 3-4 维简化快照（G3.5 重要·支持 / G3.6 重要·对抗） | 不做九维快照、内部困境轨迹；对抗侧=中等反派档 |
| L4 | 卡片（G3.7 功能·两侧） | 显式边界声明；对抗侧=小反派档 |
| L5 | 批量（G3.8 背景） | 刻板+破格 |

防跨级套用：核心才走十步深度，重要走三阶段简化，功能走卡片，背景走批量——以对应提示词文件为准。
