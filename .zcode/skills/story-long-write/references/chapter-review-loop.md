# 章后核查与修改闭环

> 本文件定义：每章正文写完（候选落盘）后，到「本章真正结束」之间的完整交互闭环。它是 Phase 5 已有散点检查（去 AI 味 / 一致性 / 错别字 / 情绪 / 语言节奏精修）之上的**统一交互封装**——把「先列问题清单 → 用户确认 → 修改 → 用户手改 → 手改提炼联动 → 上下文衔接重点核查 → 确认结束」串成一条显式流程。
> 触发：写完第 N 章候选正文后自动进入；用户也可随时说「核查本章」「对该章内容进行核查和修改」「检查这章」单独触发。
> 本文件只做「编排与封口」，各检查细则指向对应 references/脚本，不重复。

---

## 一、全流程总览

```
写完第 N 章候选
   │
   ▼ 第一段·自动核验（九项 → 只列问题清单，不直接改）
   ▼ 用户确认：要改哪些
   ▼ 执行修改（只改确认项；blocking 硬门当轮清，见「守门」）
   ▼ 用户按自己写作习惯手改一轮
   │    手改后 → 「手改提炼与下游联动」（见四）
   ▼ 第二段·上下文衔接重点核查（见五）
   ▼ 用户确认无误
   ▼ 本章结束（接纳/追踪/声线，见六）
```

## 二、第一段·自动核验九项（先列清单，不改）

| # | 核验项 | 对照标准 / 机制 | 方向 |
|---|---|---|---|
| 1 | 去 AI 味 | story-deslop Gate A-G + `anti-ai-writing.md` | 负向删冗余 |
| 2 | 语言节奏精修 | `chapter-language-revision.md` 六项 | 正向补+改 |
| 3 | 错别字 / 禁用词 | `check-typos.js` / `banned-words.md` | 确定性 |
| 4 | 人物言行符合人设 | `character-voice-anchor.md`（本章言行锚定卡回查） | 语义 |
| 5 | **风格一致性** | 本章句长/标点/比喻密度/笔调 vs `设定/文风.md` 锚点与量化规则 | 语义 |
| 6 | **腔调一致性** | 本章叙述/对话腔调 vs `genre_tone`（题材/基调）＋各人物语言特征卡 | 语义 |
| 7 | **距离调节合理性** | 本章各场景距离 vs 七级谱系（`language-distance.md`，G7.9）；有无「远↔最近」无过渡直跳；高压是否贴内心、过场是否拉远；距离走向是否呼应本章/主题 | 语义 |
| 8 | 情节链接 | 因果链干净、前后章事件承接、无断裂/凭空；**动机前置三问：①人物每个行动前是否有可见动机（为什么此刻做这件事）？②每个场景入场是否有引线（谁/什么把她带到这里的）？③每个新信息、新物件、新名单出现前是否有铺垫或由头（不能"走着走着就撞见"）？**三问任一答不出即为 major，回正文补动机/引线/铺垫，不得只靠读者脑补 | 语义 |
| 9 | 伏笔钩子 | 埋设/强化/回收正确、章首钩子承接上章、章尾钩子兑现下章 | 语义 |

> 第 5/6/7 项是本闭环新增（原 Phase 5 未显式核验第一段层）：风格、腔调、距离都有对照标准（`文风.md` / `genre_tone` / 七级谱系），核验 = 回查「本章实际写成什么样 vs 定的标准」。

## 三、问题清单输出格式

```markdown
## 第 {N} 章核验问题清单
| # | 维度 | 位置 | 问题 | 严重级 | 建议改法 |
|---|---|---|---|---|---|
| 1 | 去AI味 | 第X段 | "他感到..." | minor | 改动作 |
| 2 | 距离 | S2场景 | 高压场景用了"最远-抽象" | major | 拉近到"最近-内心" |
```

- 严重级：`blocking`（语言泄漏/HTML/截断/逐字退化——**当轮清，不进确认**）/ `major` / `minor` / `advisory`。
- 列完后**停下等用户确认要改哪些**，不自动改（blocking 除外）。

## 四、手改提炼与下游联动（承接「用户手改一轮」）

用户手改正文后，AI **不假设改动意图**，先提炼，再决定是否联动下游：

### 4.1 手改提炼（diff → 关键改动点）

对比手改前/后，提炼「关键改动点」，每条标：
- 改了什么（事实 / 人设 / 伏笔 / 关系 / 决策 / 时间线 / 价值观 / 文风措辞）
- 级别：`纯文风/措辞`（不影响下游）| `剧情/事实级`（可能波及下游）

### 4.2 波及下游判定（引用 `revision-impact-and-canon.md` 影响关系清单）

只有「剧情/事实级」改动才往下走。对照影响关系清单：正文第 N 章改动 → 必查对应细纲/卷纲/总纲/相关设定（向上）＋ N-1/N+1（同层）＋**所有命中实体/事实的后续章（向下投影）**。

**重点问一句**：这次手改，是否让「后面还没写正文的章节 / 场景卡」的设计变旧？
- 是 → 按 `revision-impact-and-canon.md` 门禁（`revision_guard.py plan` → 联动修改受影响细纲/场景卡 → `verify` 复核）；**主动提醒用户并给受影响清单，经确认才改下游设计**。
- 否 → 只做一次性事实同步。

### 4.3 事实同步

手改若改变了连续性事实（身世/血缘/关系/物权/权限/时间线/伏笔），构造 `mode=revision` 追踪事务，用 `tracking_commit.py` 同步快照/伏笔/时间线/`fact_changes`。

### 4.4 声线样本提示（学作者风格）

手改较多、或作者认为这是满意风格时，**提示**：「本章手改较多，是否纳入黄金声线样本？」同意则 `voice_profile.py golden-build --chapters "..."` 精选入样本。新章写前 `voice_profile.py check` 把黄金样本作为更窄的模仿方向（对应 `accepted-voice-profile.md`「黄金声线样本」）。

## 五、第二段·上下文衔接重点核查

手改+联动后，对本章做**跨章衔接**重点核查（区别于第一段章内检查，这里看前后勾连）：

| 核查点 | 问法 |
|---|---|
| 伏笔 | 本章埋的伏笔是否与前文埋设/后文回收计划钩得住？强化/回收是否踩在正确章？ |
| 钩子 | 章首钩子是否真实承接上章章尾？章尾钩子是否给下一章留了可兑现入口（无死钩）？ |
| 节奏 | 本章在全书节奏曲线上位置合理？蓄力-引爆-余韵与上下章衔接？无突兀断崖/拖沓 |
| 人物言行跨章 | 本章言行与上章状态一致（除非本章有弧线节点）？无「人设突变」 |
| 距离走向 | 本章距离最终走向呼应上章收束与下章开局？无跨章距离割裂 |

逐项出「✅ 衔接正常 / ⚠️ 需说明」；⚠️ 项给处理建议，等用户确认后落实。

---

## 六、本章结束（收口）

全部通过且用户确认后本章才算结束：
1. 候选稿按「章节候选、接纳与投影自检」协议，经用户明确接纳后入 `正文/` 并提交追踪；
2. 声线画像按 `accepted-voice-profile` 生命周期 `update`；
3. `追踪/质检进度.md`（若部署）对应章节行列打 `✓`；
4. 收口时提示用户：接纳闭环完成后可说「本章已定稿，请核查」触发定稿核验（`post-commit-audit.md`）——那是定稿后的设计层一致性审计与双向裁决，本闭环（候选稿质检）不替代它。

---

## 守门

- **blocking（语言门/HTML/截断/退化）当轮清**，不因「等确认」跳过；与「先列清单」不冲突（清单只装语义/风格类问题）。
- **手改提炼是强制步骤**：用户手改后必须提炼，不得假设没改或假想改动意图；波及下游未写的细纲/场景卡时，必须提醒并给受影响清单，经确认才改下游。
- 细则不在此重复：去AI味 → story-deslop / anti-ai-writing；语言节奏 → chapter-language-revision；人物言行 → character-voice-anchor；修订影响 → revision-impact-and-canon；声线 → accepted-voice-profile。
