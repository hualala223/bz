# 全书流程步骤地图（唯一权威）

> 目标：把「立项 → 完本」的整条链路写成一张可导航的地图。任何时刻只回答三问：**我现在在哪一步？上一步的产物是什么？下一步该说哪句触发词？**
> 本文件是全流程步骤的唯一权威；各 Skill 的 SKILL.md 头部「位置」声明、story-stepwise 门表、openbook 的 OB 门均指向本表，不一致时以本表为准。
> 双源立场：门结构取《小说设置提示词》（逐决策点确认），门内容与产物轨道取原版 oh-story（markdown + JSON 双权威 + 脚本 Gate）。二者并集共存，不互相替换。

---

## 总图

```
0 立项 → 1 开书（含四锚定门）→ 2 文风精化(可选) → 3 约束清单门 → 4 人物设计(G3.0→G3.9)
      → 5 大纲(体量/卷纲/粗纲/细纲/场景卡) → 6 正文(写前→写→章后) → 7 卷末体检
      → 8 审查/去味 → 9 发布
```

## 各阶段六要素

### 阶段 0 立项
- **触发词**：「我要写一本 XX 书」「帮我扫榜选方向」「帮我看看现在什么题材火」
- **操作内容**：扫榜选题 → `选题决策.md` → 方向确认 → 对标登记（主/副对标）
- **操作标准**：按 `story-long-scan`（市场）＋ `story-long-write` Phase 1（对标发现）；判定环节走判断显式化三段式
- **确认门**：选题门（三行摘要：题材方向/核心情绪/目标体量建议）
- **产物**：`选题决策.md`（扫榜链）+ 对标登记
- **责任 Skill**：`story-long-scan` → `story-long-write` Phase 1
- **下一步**：「确定方向了，说『开书设定』」

### 阶段 1 开书（OB-0~9，含四锚定门）
- **触发词**：「开书设定」「从灵感开始做设定」「按提示词开书」
- **操作内容**：OB-0 前置加载 → OB-1 篇幅三连 → **OB-1.5 书名（定暂定名 + 建 `{书名}/` 目录 + `.active-book`）** → OB-2 故事蓝图 → OB-3 定位（**含时间/地点/背景锚定**）→ OB-3.5 文风 → OB-3.6 平台读者 → OB-3.7 情感关系基调 → OB-3.8 对抗层级与副线结构 → OB-4 分卷 → OB-5 主题 → OB-6 世界观（**含金手指有无先导确认**）→ OB-6.5 金手指专项设计（仅有金手指时）→ OB-7 类型适配 → OB-8 象征锚点 → OB-9 归档（九项联动 + 四锚定齐全）
- **操作标准**：决策点表见 `story-openbook/references/confirmation-gates.md`；交互协议见 `story-stepwise/references/interactive-protocol.md`
- **确认门**：OB 门逐门确认；**四锚定门（OB-3/3.5/3.6/3.7）先于大纲，锚定即 A 类硬约束**
- **产物**：`{书名}/设定/_开书.json`（含 `book_title`、`time_anchor`/`place_anchor`/`style_anchor`/`platform_profile`/`audience_profile`/`emotional_relations`）、`{书名}/设定/故事蓝图.md`、`{书名}/设定/主题.md`、`{书名}/设定/题材定位.md`（含平台画像节）、`{书名}/设定/文风.md`、`{书名}/设定/世界观/*.md`；**全部门产物落 `{书名}/` 目录（OB-1.5 已建 + `.active-book` 指针），不在项目根裸放**
- **责任 Skill**：`story-openbook`
- **下一步**：「开书完成，说『出约束清单』或先『定文风』精化」

### 阶段 2 文风精化（可选）
- **触发词**：「精修文风」「重设风格」「语言风格设计」
- **操作内容**：在 OB-3.5 简化锚定之上，走 style-spec 全流程（风格定调/视角七级距离/量化规则/开篇规范/语言特征卡）
- **操作标准**：`story-style-spec/SKILL.md` 步骤 0-6
- **确认门**：步骤 1-6 逐项
- **产物**：覆盖 `设定/文风.md` 为精化版
- **责任 Skill**：`story-style-spec`
- **下一步**：「文风确定，说『出约束清单』」

### 阶段 3 约束清单门
- **触发词**：「出约束清单」「列设定约束」「扫描设定」
- **操作内容**：扫 `设定/_开书.json` + `设定/*.md` → A 硬/B 软/M 元数据三表 → 逐条报告（硬阻断不概括）→ 确认
- **操作标准**：`story-constraint-gate/SKILL.md`；字段路径对照 `references/field-mapping.md`；四锚定产物为 A 类来源
- **确认门**：三表逐条确认
- **产物**：`大纲/_约束清单.md`
- **责任 Skill**：`story-constraint-gate`
- **下一步**：「约束清单确认，说『人物设计』」

### 阶段 4 人物设计（G3.0→G3.9）
- **触发词**：「人物设计」「设计主角」「设计反派」「给 XX 做深度人设」「人物交叉核查」
- **前置**：`length_params` 四字段已在开书 OB-1「篇幅三连」确认（章数/每章字数/总字数/档位）——人物各层数量公式与出场密度均消费它，缺失先回 `story-openbook` OB-1 补齐。
- **操作内容**：按十步门链 G3.0→G3.9 逐步设计+确认+推进（五层结构 × 六型阵营迁移 × 反派四档）。总流程固定为三段：**（一）G3.0 按篇幅定各层人数 ＋ 六型阵营迁移登记（faction_arc）＋ 反派四档标注（villain_tier，仅对抗侧）＋ 关系网络&情感关系门 →（二）G3.1→G3.8 逐人按层标准设计 →（三）G3.9 全人物核查**。权威总图见 `story-character-lab/SKILL.md`「执行总流程」节。
- **两个易错点（执行不得误解）**：① 对抗侧角色除「层」外还须标「反派四档」（小/中等/大弧/最终Boss），层与档正交；② 六型阵营迁移中，「→中立」是独立第三态——**反派→中立 ≠ 算主角支持力量**，中立只算中立（落点归属：→对抗算对抗、→支持算支持、→中立算中立）。
- **操作标准**：`story-character-lab/SKILL.md` 十步门链 + `references/depth-modules.md`；层级标准见下表（主角+最重要反派单独成 L1 层）
- **确认门**：每步确认；断点 `blocked_at_G3.X` 可用「继续执行 G3.X」恢复
- **产物**：`设定/角色/_人物框架.md`（faction_arc 状态机）、`设定/关系.md`（情感关系小节）、逐角色深度小节
- **责任 Skill**：`story-character-lab`
- **下一步**：「人物做完，说『写大纲』/『体量总览』」
- **中途补人/改人**：大纲期/正文期需要新增或修改人物时，不重跑全书 G3.0→G3.9——说「增量补人」「改XX人设」，走下方专节「中途补人与改人」

### 阶段 5 大纲
- **触发词**：「写大纲」「体量总览」「写粗纲」「出粗纲」「出细纲」「场景卡」「把第 N 章拆成场景」
- **操作内容**：四张约束表 → 体量/卷纲（卷门）→ 情节粗纲（粗纲门）→ 逐章细纲（纲门）→ 场景卡（场景门）
- **操作标准**：`story-long-write/references/workflow-setup.md` Phase 3（体量门+卷纲）+ `story-outline`（粗纲）+ `story-outline-detail`（细纲）+ `story-scene-card`（场景）；约束清单前置
- **确认门**：体量门 → 卷门 → 粗纲门 → 纲门 → 场景门（stepwise 粒度）
- **产物**：`大纲/大纲.md`、`卷纲_*.md`、`粗纲_*.md`、`粗纲总表.md`、`细纲_第NNN章.md`、`场景卡_第NNN章.md`
- **责任 Skill**：`story-long-write` Phase 3（体量门+卷纲）+ `story-outline`（粗纲）+ `story-outline-detail`（细纲）+ `story-scene-card`（场景）
- **下一步**：「细纲/场景卡就绪，说『写第 1 章』」
- **中途补人**：细纲冒出非主线会复用配角 → 细纲步骤 8 路由「增量补人」；场景卡发现新具名人物 → 场景卡层禁止造人，输出欠账点回细纲触发补人，补完场景卡重跑该章（未落盘从头走、已落盘只重做受影响场景）。见下方专节

### 阶段 6 正文
- **触发词**：「写第 N 章」「写第 1 章」「日更」「续写」「继续写」
- **操作内容**：写前门 → 候选章 → 语言/文风/对白 Gate → 章后门 → 接纳/定稿
- **操作标准**：`story-long-write` Phase 4/5 + `references/workflow-daily.md`；候选不等于接纳
- **确认门**：写前门 → 章后门；「接受/定稿」才入正文+追踪
- **产物**：`正文/第XXX章_*.md` + 追踪
- **责任 Skill**：`story-long-write` Phase 4/5
- **下一步**：「本章定稿，说『写下一章』或『卷末体检』」

### 阶段 7 卷末/完本体检
- **触发词**：「卷末体检」「完本检查」「这卷写完了帮我查一下」
- **操作内容**：脚本预检 → 直觉初读 → 冲突密度 → MICE → 伏笔闭环 → 开篇结尾镜像 → 情绪曲线 → 时间线地理抽查 → 八项总检
- **操作标准**：`story-final-check/SKILL.md`；时间线地理参照 OB-3 `time_anchor`/`place_anchor`
- **确认门**：综合修改清单确认
- **产出**：体检报告 + 修改清单
- **责任 Skill**：`story-final-check`
- **下一步**：「体检通过，说『审查』或『去 AI 味』」

### 阶段 8 审查/去味
- **触发词**：「审查一下」「去 AI 味」
- **操作内容**：多视角审查（按 `platform_profile` 取平台 rubric fanqie/qidian/zhihu）→ 去味保护改写
- **操作标准**：`story-review/SKILL.md` + `story-deslop/SKILL.md`
- **确认门**：审查回执 / 去味确认
- **产出**：审查报告 + 改写稿
- **责任 Skill**：`story-review` + `story-deslop`
- **下一步**：「定稿完成，说『准备发布』」

### 阶段 9 发布
- **触发词**：「准备发布」「生成发布材料」「发布到番茄」
- **操作内容**：release-package（书名/简介/标签/清单）→ publish（预检/存草稿/发布）
- **操作标准**：`story-release-package/SKILL.md` + `story-publish/SKILL.md`；消费 `platform_profile`
- **确认门**：发布材料确认 + 发布授权
- **产出**：发布清单 + 平台发布
- **责任 Skill**：`story-release-package` + `story-publish`

## 中途补人与改人（跨阶段小流程）

> 适用：阶段 5 粗纲/细纲/场景卡、阶段 6 正文期间需要**新增人物**或**修改已有人物**。前提：阶段 4 的 G3.0 人物框架已建（`设定/角色/_人物框架.md` + C/M/F/B 代号体系）；框架未建则回阶段 4 走完整「人物设计」流程。权威定义：`story-character-lab/SKILL.md`「增量补人与改人模式」节。

| 事项 | 触发词 | 流程走向 | 产物 |
|---|---|---|---|
| 新增人物（非主线会复用配角） | 「增量补人」「细纲补人」「给XX补深度人设」 | 触发位置（细纲步骤 8 / 卷纲粗纲欠账回补）→ `story-character-lab`：层级判定（判断显式化三段式）→ 代号分配（取该层未用最小序号）→ 按层 G3.x 标准逐子步骤深度设计（不降档）→ 建 `设定/角色/{编码}_{人物名}.md` → 登记 `_人物框架.md`（faction_arc + 出场密度重算）→ G3.9 相关子集局部核查 → 报告「已可回到触发步骤」 | 新人物卡 + 框架更新 |
| 新具名人物出现在场景卡 | —（场景卡自动欠账） | 场景卡输出「素材不足欠账点」停止 → 回细纲触发上一行 → 补完细纲落盘停靠 → 场景卡**重跑该章**（未落盘从头走本章流程、已落盘只重做受影响场景） | 同上 + 该章场景卡 |
| 修改已有人物 | 「改XX人设」 | 先走跨产物修订门禁做只读影响分析（`追踪/修改影响/active.json`）→ `story-character-lab` 改人模式：只重设计受影响模块（伤及性格内核/弧线锚点/深度模块才重做对应子步骤）→ 同步回写框架/关系卡、登记 `_meta.modifications` → 局部核查 + `phase=verify` 复核 → 受影响的细纲/场景卡按过期重跑 | 修订后人物卡 + 影响清单 |
| 主线级新人物 | —（须先过卷纲/粗纲） | 细纲/场景卡只标「欠账点」回卷纲/粗纲，经确认进入后再走「增量补人」 | 同上 |

**边界**：L1（主角/最重要反派）级新增须用户显式确认；一次性路人/无戏份配角不建档（归 L5 背景组）；禁止只写速记卡、禁止用 `{名}.md` 无编码命名。

## 快速模式说明

用户明示「快速模式」→ 确认门整体跳过（各 skill 只保留自身停靠点：细纲交付、单轮 ≤3 章候选），但**硬规则照旧**：中文锁定、字数目标、落盘、语言/文风/对白 Gate、约束清单前置、四锚定产物仍须存在（快速开书走 `story-long-write` Phase 1-2 一次性表单，同一字段，见 workflow-setup.md「双轨对齐」）。
