# story-openbook：开书设定交互向导

## 定位与守门

- **位置**：全书流程第 1 阶段（开书，含四锚定门），见 `story-stepwise/references/book-roadmap.md` 阶段 1。上一步=选题门（story-long-write Phase 1）；下一步=约束清单门/人物设计（`story-constraint-gate`/`story-character-lab`）。

- **机制来源**：用户自有《小说设置提示词》第一组（G1.0-G1.7）与第二组（G2.0-G2.5）的确认项目，适配 oh-story 目录约定，属用户本人资产。完整决策点表见 [references/confirmation-gates.md](references/confirmation-gates.md)，按门编号检索。
- **何时触发**：用户说「帮我开书 / 开书设定 / 从灵感开始 / 先做设定 / 按提示词开书」且要求逐项确认（逐步确认模式默认叠加本 skill）；或用户主动点名。用户说「快速模式」时不加载本 skill，走 story-long-write 原生 Phase 1-2 一次性产出。
- **与既有 skill 的关系（强强结合，不是替代）**：
  - 本 skill 只做「设定」：逐决策点确认后落盘 `{书名}/设定/` 目录与 `{书名}/设定/_开书.json`。
  - 交棒：「写大纲」→ `story-long-write` Phase 3（消费上述产物）；「人物深度设计」→ `story-character-lab`；「精修文风」→ `story-style-spec`（OB-3.5 已锚定简化版，本 skill 用于精化）；「写第1章」→ `story-long-write` Phase 4。
  - **与 `story-stepwise` 协同**：本 skill 自身即逐决策点确认，加载它时 `story-stepwise` 的「选题门 / 人物门 / 体量门」三道门由本 skill 的 OB-1~OB-4 覆盖（P2-2 更名后现行门名），不再重复停下；卷纲/细纲/写前/章后各门仍由 stepwise 负责。
  - 人物、细纲、场景、风格的深度模块仍由各自 skill 负责，本 skill 不重复实现。
- **前置**：空项目直接开始（由 OB-1.5 书名门先建 `{书名}/` 目录）；已有项目先读 `{书名}/设定/`、`{书名}/追踪/上下文.md` 判断已过门，只补缺失门，不重复已确认项。
- **产物防漂移**：`{书名}/设定/_开书.json` 是设定阶段唯一结构化权威（累积 project_state），其余 `{书名}/设定/` 文件均为其可读视图；进入大纲后由 `{书名}/追踪/_tracking-state.json` 接管权威。

## 运行模式（沿袭提示词「全局自动扩展策略」）

| 模式 | 缺失参数处理 | 公式计算 | 可选扩展 | 确认粒度 |
|------|-------------|---------|---------|---------|
| A（手动） | 必须请求用户提供，不得用默认值 | 计算后展示、需用户确认 | 用户明确要求才执行 | 每项均确认 |
| B（智能自动，默认） | 按缺失处理规则计算或取默认，并告知用户 | 自动应用计算结果 | 按自动触发条件自判 | 仅核心参数确认 |
| C（全自动） | 自动填充全部缺失项并输出摘要 | 自动应用 | 全部执行 | 跳过确认 |

用户随时可说「切换到模式A/B/C」或「跳过/执行某扩展」，本 skill 立即遵从。

## 交互协议（每道确认门通用，五步）

1. **素材请求**：进入篇幅/主题/世界观决策前，先问「有没有对标作品或参考资料？没有就直接答下面的问题。」收到素材则标注「【素材参考】」并提取借鉴元素；没有则按默认推进。
2. **推荐草案**：AI 先算推荐值并给理由（量化推演→对标作品→经典母题），以草案形式展示，禁止让用户从空白开始填。
3. **启发循环（卡壳时自动启动）**：用户回复「没想法/不知道/再给点例子/换一批/嗯……」等视为卡壳 → 每轮换一个启发维度（经典母题/高概念混搭/对标作品/角色视角/意象感官/极端情境/反向假设/量化推演），每轮结束问「这一批有让您产生想法的吗？还是我换个角度再给一批？」；连续 3 轮无选择 → 提议占位默认并标 `[占位待复核]`；用户说「你来定」→ AI 基于上下文选最优并请确认。
4. **确认话术**：记录前必问「您确定采用 [具体内容] 吗？确认后我将更新配置并继续。」；未确认不更新 `_开书.json`。
5. **累积与受阻**：每门通过后整份更新 `{书名}/设定/_开书.json`（完整累积，禁止 `...`/省略/占位；修改进 `_meta.modifications`；依赖尚缺的字段置 `null` 并进 `pending_fields`）；任一门因前置数据缺失受阻 → `_meta.execution_status="blocked_at_<门>"`，报缺失字段与期望来源，提示「补充后输入『继续执行 <门>』从断点恢复」。

## 产物（oh-story 目录约定）

- `{书名}/设定/_开书.json`：设定阶段唯一累积权威（完整 JSON，字段以 `references/confirmation-gates.md` 为准，不缩写）。
- `{书名}/设定/故事蓝图.md`：G1.7 故事种子文档的可读版（原始灵感/核心冲突/LOCK/三幕种子/主旨/核心矛盾/定位摘要）。
- `{书名}/设定/主题.md`：主题金句、价值光谱（正面/相反/矛盾/否定之否定）、心结三层溯源。
- `{书名}/设定/题材定位.md`：按 `story-long-write` 的 `artifact-protocols.md` 模板填（基本信息/读者契约/终局底牌与升级台阶/核心梗三分法/对标登记）+ 平台与读者画像节（OB-3.6 产物，供 review/publish/release-package 消费）。
- `{书名}/设定/世界观/*.md`：时代背景（**时间锚定起点/跨度/推进规则 + 年代/地点/社会文化政治科技，含冲突功能说明**）、地点空间层级（OB-3 地点锚定）、力量体系、社会结构、金手指（OB-6.5 独立产出 `金手指.md`）与象征（OB-8 `象征.md`）等，按主题拆分，每条规则标注「能制造什么冲突」。
- 交棒时展示：已完成门摘要 + 下一步建议（说「写大纲」→ story-long-write Phase 3）。

## 受阻恢复

- 任一门缺前置数据 → 置 `blocked_at_<门>`，输出缺失字段与来源，指引「补充后输入『继续执行 <门>』」。
- 中途退出重进：读取 `{书名}/设定/_开书.json` 的 `_meta.execution_status` 与 `pending_fields`，从对应门前置校验处恢复。

## 交棒约束清单门

- OB-8 全部通过、交棒 `story-long-write` Phase 3 前，**先运行 `story-constraint-gate`**：把 `{书名}/设定/_开书.json` + `{书名}/设定/*.md` 扫描成 A 硬约束/B 软约束/M 元数据三表，逐条向用户确认后落盘 `{书名}/大纲/_约束清单.md`——这是 Phase 3 四张约束表（character_chapter_map 等）与细纲/场景卡各步校验的输入。
- 用户说「先出约束清单」或进入大纲流程时，按 `story-constraint-gate` 的流程执行；字段路径对照 `story-constraint-gate/references/field-mapping.md`。
