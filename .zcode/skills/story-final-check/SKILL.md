# story-final-check：完稿体检

## 定位

`story-review` 管**连载中**的单章/批次审查；本 skill 管**卷末或完本**的整体体检，两者互补不替代。输入：指定范围的 `正文/` ＋ `追踪/` ＋ 对应细纲/卷纲。**全书位置**：阶段 7 卷末/完本体检，见 `story-stepwise/references/book-roadmap.md`。

交互通用规则（卡壳信号/八维启发/3 轮终止占位/素材请求/A-B-C 模式）见 `story-stepwise/references/interactive-protocol.md`；本 skill 各 ⏸️ 交互点按该协议执行。

## 流程

0. **定范围 + 冷却确认门 + 作者侧状态两问**：
   - 确认对象（第 X 卷 / 全书）。
   - **与长篇卷末顺序冷读的衔接**：卷末体检前先检查 `追踪/冷读/{run-id}/`（story-long-write 卷末顺序冷读产物）。若该卷 S1/S2 未清（AGENTS.md 与 long-write 的「S1/S2 未清不得开新卷」规则），本 skill 先提示完成冷读或把冷读 issue 并入本体检；冷读发现的 S1/S2 与体检冲突密度/伏笔/人物一致性发现重复时去重并互引产物路径。
   - **冷却确认门（硬门，⏸️ 等待用户输入，用户回答前暂停执行）**：请用户三选一声明冷却期状态——
     - **已冷却 N 天**：记录天数；N≥3 天（理想 ≥14 天）按全权重初读，N<3 天标注「冷却不足，初读权重略降」；
     - **未冷却但要求立即体检**：记录「未冷却」，体检报告头部标注「初读结论权重下调」；
     - **跳过冷却**：记录「跳过」，视同未冷却，同样在报告头部标注权重下调。
     ⚠️ 严禁自行假设冷却状态——必须先提问并等待用户回应（机制来源：G8.0 §1.3 冷却期状态未声明时的交互逻辑，L107-128）。
   - **作者侧状态两问（⏸️ 等待用户输入）**：
     1. 批评家/拖延者等内在声音对本次审稿/修改的干扰是否严重？（有/无）
     2. 本次体检暴露的修改困难是否值得记录与转化？（有/无）
     - 两问均答「无」→ 跳过内在声音环节，报告标注「内在声音：用户报无，跳过」；步骤 4 的「困难与转化」小节照常保留（空或简记）。
     - 任一答「有」→ 进入文末「简化内在声音工作表」：四类问卷精简为批评家/拖延者两问（审判者/受害者有困扰可一并录入），每行填「它说了什么 / 事实还是恐惧 / 回应反驳 / 行动计划」，并产出 3-5 条积极信息候选供用户确认（机制来源：G8.1 §2.2 四类问卷 L630-639、§2.3 辅助填表 L641-652、§2.4 积极信息 L654+、§2.1.3 跳过处理 L621-628）。

1. **直觉初读四维**：按 节奏 / 情绪 / 人物 / 逻辑 四维通读抽样章节，每个问题含章节号＋一句描述＋强度 1-5；无问题的维度明确写「无」，四表必全。

2. **量化体检**（抽样：≤50 章抽 5 章、51-120 抽 8-10、>120 抽 12-15，必含各阶段边界章）：
   - **脚本预检（确定性预检，只报告不改写）**：对范围内全部 `正文/` 文件运行仓库脚本（路径相对项目根目录），结果汇总进体检报告「脚本预检」小节：
     - `node .zcode/skills/story-long-write/scripts/check-typos.js --check 正文/…`——错别字固定搭配；
     - `node …/check-emotion-floor.js --check --pressure=high|low 正文/…`——情绪落地三通道下限（高压/过场章须分组调用，默认 normal）；
     - `node …/check-hook-strength.js --check 正文/…`——章尾钩子下限；
     - `node …/check-ai-patterns.js --check 正文/…`——16 类 AI 句式；
     - `node …/normalize-punctuation.js --check 正文/…`——省略号/破折号/引号归一（`--check` 只报告不改写）；
     - 按需 `node …/check-degeneration.js --check 正文/…`——退化/英文泄漏。
     预检阶段不把退出码当闸门（exit 1 仅表示有命中，属预期）；**脚本缺 npm 依赖或运行失败 → 降级为人工规则核对**（按同一批检查点逐项人工过）并在该小节标注「脚本预检降级」；所有命中须人工确认后才可改稿，脚本永不自动改写。
   - **冲突密度** = 含冲突场景 ÷ 抽样场景总数，健康区 0.6-0.8（<0.6 平淡 / >0.8 过载）；
   - **伏笔闭环率**：对照 `追踪/伏笔.md` 与各卷纲逐条核对，目标 ≥80%；未回收 / 过早回收 / 回收无强化逐条列出；
   - **基因纯度（MICE）**：分卷统计四类场景占比——Milieu 环境（世界/地点探索）、Idea 观念（主题/问题探索）、Character 人物（角色成长/转变）、Event 事件（情节推进）；每卷输出 `milieu_pct / idea_pct / character_pct / event_pct`（抽样沿用本步骤规则、范围不明先问用户再算，⏸️ 可交互确认）；总体健康度三档：**healthy 均衡**（主导象限 ≤45% 且无象限缺失）/ **mild 单极化**（主导 45%-60% 或某象限占比 <5%）/ **severe 失衡**（主导 >60% 或某象限为 0）；附重复场景 / 重复人物 / 重复事件清单；结果写入报告 MICE 小节，并作为**关联分析数据源**：Event(E) 占比与冲突密度均值正相关检验（双低 → 标注「事件占比与冲突密度双低，需强化情节驱动力」）、重复事件是否造成冲突密度虚高、情绪曲线峰值与 MICE 关键节点是否错位。
   - **副情节收束检查**：以 `大纲/卷纲` 剧情单元＋`追踪/伏笔.md` 提取副线清单（清单缺失 → ⏸️ 交互补全：用户提供或授权 AI 识别并标注「待确认」）；逐条核对收束状态——**已闭环**（文本有明确收束场景）/ **未闭环**（埋下线索无后续交代）/ **开放式**（有意留白）/ **延续**（明确设计为跨书副线，需用户在设计文档标注）；逐条评估对主线影响（强关联/弱关联/无关联）与跨卷间隔（合理/过长/过短，单卷为不适用）；判定为**入侵性子情节**（删除后主线完全不受影响且占用篇幅较多）与弱关联子情节者，连同判定理由列入步骤 4 修改清单（建议删除或合并 / 强化关联或精简）；未收束副线若与初读「逻辑与情节疑惑」吻合，标注「与初读感受一致，需重点收束」。
   - **开篇结尾镜像**：开篇场景与结局 ≥2 组元素呼应（物件/台词/处境/关系/象征），呼应不上即列修改建议；
   - **情绪曲线**：实际紧张走势对照细纲「阶段位置」设计，标出持续过高 / 过低 / 峰值错位的章节段；
   - 时间线与地理抽查 3 处；字数分布 vs 细纲目标偏差排行。

3. **人物行为一致性抽查**：主要角色各抽 3 个关键行为做四判定——一致 / 合理演变 / 断裂 / 数据不足；断裂项定位到具体章节并给出与档案的出入点。

4. **综合修改清单**：合并以上全部发现（含脚本预检命中、入侵性子情节、MICE/副情节问题）→ 去重 → 高/中/低优先级 → 每条附修改方向。另设「困难与转化」小节：本次体检暴露的创作困难、根源猜测、转化想法（与步骤 0 作者侧状态问 2 联动；沉淀为你的个人经验库）。

5. **读者反馈与外部审阅（可选，⏸️ 等待用户输入）**：询问用户是否有外部反馈（测试读者评论 / 编辑意见 / 评论等）需要纳入——**反馈只来自用户粘贴，本 skill 不扮演读者、不模拟读者**（机制来源：G8.13 外部读者反馈数据 = 用户输入）。
   - 无 / 跳过 → 记录「无外部反馈」；
   - 有 → 用户粘贴反馈摘要 → 提取关键问题并分类（情节理解/人物认同/节奏感受/语言风格/逻辑困惑/代入感）→ **共性问题 = ≥2 人提及的相同或高度相似问题** → 优先级排序：**高**（共性且影响核心理解）/ **中**（共性但仅影响体验，或个别严重逻辑问题）/ **低**（个别主观偏好）→ 若与作者设计意图（核心冲突/主题/人物弧线）冲突，两案并陈：**方案A 坚持原设计**（微调让读者更好接受）与**方案B 采纳反馈**（调整设计并说明对故事的影响），由用户最终决定 → 产出最终修改计划（含涉及章节、预估工作量）记入体检报告；其中高/中优先级条目并入步骤 4 综合修改清单并注明「来自外部反馈」。样本充足时附整体满意度与代入感评估，样本不足标「无数据」。

6. **八项总检判定**（逐项 通过/部分/不通过）：核心冲突贯彻 ／ 主题贯穿 ／ 主角信念演变完整 ／ 伏笔闭环率达标 ／ 篇幅偏差 ≤20% ／ 风格遵循文风文件 ／ 卷间衔接 ／ 格式规范。
   结论三档：**可进入下一卷或投稿** / 建议修订后再判 / 需系统性返工（附返工范围建议）。

7. 产物落盘：`追踪/体检_{第X卷|全书}.md`。具体修改执行走「修改第X章」。

> 判定是参考结论不是判决：是否完稿由你决定，本 skill 负责把问题摆全、摆准。

## 体检报告结构（落盘必含）

`追踪/体检_{第X卷|全书}.md` 依次包含：元信息（范围 / 冷却状态及权重标注 / 作者侧状态）→ 脚本预检（含降级标注）→ 直觉初读四维 → 量化体检（冲突密度 / 伏笔闭环率 / 基因纯度 MICE / 副情节收束 / 开篇结尾镜像 / 情绪曲线 / 时间线地理 / 字数分布）→ 人物行为一致性 → 综合修改清单（含困难与转化）→ 读者反馈（可选）→ 八项总检 → 下一步建议。
