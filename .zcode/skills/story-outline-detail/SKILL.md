# story-outline-detail：情节细纲（逐章展开层）

> **全书位置**：阶段 5 大纲的「纲门（原 G5）」，介于粗纲与场景卡之间，见 `story-stepwise/references/book-roadmap.md`。
> **三步骤分离**：粗纲（`story-outline`）→ **细纲（本 skill）** → 场景卡（`story-scene-card`）。细纲只展开「每章怎么发生」，不产出镜头级场景卡（那是 story-scene-card 的责任），也不追溯改粗纲已确认的结构骨架。

## 方法论来源与双源声明

本 skill 以源 A（原版 `story-long-write` Phase 3 细纲流程）为**主体**，注入《小说设置提示词》**第五组 G5.0→G5.6** 的强化字段与校验（源 B）。`G5.0` 的 S 公式与 `G5.3` 的节奏检查第一期已对齐，本 skill 沿用不重复造。

**双源声明（本节为唯一权威，改本 skill 前先对照 `story-constraint-gate/references/merge-directive.md`）**：
- 细纲主体（细纲模板/大纲安全七检/爽点五字段/收变开留存/剧情批滚动/脚本链）＝源 A；
- 强化注入（α点逐字段溯源、α点-心路阶段对齐表、α点-爽点对齐、补充事件库按心路阶段对齐、四部分事件密度+空白章校验、关系变化节点保护）＝第五组 G5.x；
- 产物轨道＝源 A（markdown `大纲/细纲_第NNN章.md`，第五组 JSON 片段只作生成中间态、不落盘为第二权威）。
- 人物增量补全路由（步骤 8 → `story-character-lab` 增量补人/改人模式）＝本工作区新增机制（merge-directive 取长登记「人物增量补人/改人闭环」行），非源 A/B 既有内容。

## 粗纲让渡字段的接管闭环（必读）

粗纲（`story-outline`）明确让渡给本 skill 的字段，本 skill **显式接管**，搬家不丢：

| 粗纲让渡项 | 本 skill 承接位置 |
|---|---|
| α点三要素（目标→障碍→代价+情绪弧线） | 下方细纲模板「α点」行 + α点对齐校验 |
| 五段式内容概括 | 「内容概括（五段式）」节 |
| 情节点序列（按字数预算） | 「情节细化」节 |
| 爽点五字段（角色/类型/级别/蓄力目标/蓄力进度）逐章闭环 | 「爽点五字段」行 + highlight-system |
| 伏笔逐章登记（埋设/强化/回收） | 「情节安排」「结尾设定」+ 伏笔登记 |
| 副线推进（`subplot`，SP-XX·功能·本章推进） | 「情节安排（多线）」的「副线推进」行 |
| 幽默/立场/超越/worse_off/stakes_tags 逐章检查 | 「契约风险」行 + 细纲节奏检查 |

粗纲交付的 `core_event`（每章一句话事件）+ `highlight_preset`（爽点预判）是本节 α点与爽点五字段的展开输入；粗纲已确认的结构骨架（四部分/转折点/对抗层级/心路阶段）这里**只消费、不改写**，确需改走「跨产物修订门禁」。

## 守门

- **卡壳/交互**：卡壳信号识别、八维启发轮换、3 轮终止占位、素材请求、判断显式化三段式、A/B/C 自动扩展模式 → 共享 `story-stepwise/references/interactive-protocol.md`，不重复定义。
- **前置硬门**：没有粗纲（`大纲/粗纲_第X卷.md`）或没有 `_开书.json` 的 `length_params`，不做细纲——先回 `story-outline` 补粗纲、或回 `story-long-write` 补体量门。缺 `大纲/_约束清单.md` 按 `story-constraint-gate` 规则先补。
- **不越界**：细纲不产出镜头级场景字段（地点镜头/节拍链/字数预算→ story-scene-card）；不擅自造粗纲没有的新主线人物/新反转——主线级缺口标「欠账点」回粗纲/卷纲。展开中自然涌现的**非主线会复用配角**不属越界，但必须走步骤 8「人物增量补人流程」按层级深度设计，不得顺手建档了事。
- **可支撑性保证（承接第六组「补充场景」职责）**：细纲负责给足本章每个场景的事件素材——第六组 G6.1 的「补充场景类型库 8 类」在本流程中由细纲层的「补充事件库 8 类」承接（见 references 第五节），即细纲补足的「事件」就是场景卡切分的素材来源。场景卡层不再自行补事件，只做「可支撑性回查」，发现不足回本步骤补。落地标准：细纲的情节点序列 + 补充事件数 ≥ 计划场景数 × 每场景最低事件支撑。
- **逐章必须有文件**：每章一个 `大纲/细纲_第NNN章.md`，不允许跳章。

## 流程

### 0. 读前序

读 `大纲/粗纲_第X卷.md`（逐章 core_event + highlight_preset）、`大纲/粗纲总表.md`（四部分/转折点/伏笔/节奏）、`大纲/_约束清单.md`、`设定/_开书.json`（length_params）、`设定/角色/`。**完成标准**：能一句话说出本章的目标情绪、必须兑现的情节点、章尾钩子，以及本章在粗纲结构骨架中的位置。

### 1. 细纲自适应参数（G5.0 沿用）

按 `length_params.total_chapters`（C）决定详细档：

| C | 详细程度 |
|---|---|
| ≤50 | 全部章节走完整模板 |
| 51-120 | 关键章（转折/高潮/单元首尾/伏笔引爆）完整模板；普通推进章走「最小字段集」档 |
| >120 | 仅转折点/单元首尾章完整模板，其余一行速览 + α点单行确认 |

事件素材数 `S=max(2,min(5,round(words_per_chapter/800)))` 先定 S 再排情节点；S 不足从补充事件库补。节奏粒度 `G_outline=max(2,min(10,floor(C/30)))`。**字数口径：`words_per_chapter` 与本 skill 全部字数目标/预算一律指纯字＝汉字数（不含标点符号与其他字符），量具＝prose_metrics 汉字计数（见 long-write「字数验收权威」）；S 公式输入按纯字代入，不因口径另增情节数。**

### 2. 大纲安全七检 + 大纲安全审查（批次级）

- **七检**（批次级必答；逐章只复答⑥⑦并写入「契约风险」行）：①本卷交付什么情绪②本卷核心冲突③卷节奏起承转合④新埋/待回收伏笔⑤章节定位分布（高低层次、低压+过场≤15%）⑥本章处全书哪阶段、可释放/必压住什么⑦读者契约/主角代理权/期待债/终局储备评「契约安全/需补强/契约破坏」。
- **安全审查**（批次级一次）：先按 `references/emotional-methods.md` 设计正向情绪发动机，再按 `reader-contract-and-progression.md` 做因果权+结算权、关键节点四问、期待所有权诊断；再做两个可证伪降级检查（①删掉题材核心对象后是否退化②删掉主角后情绪兑现是否不变）。`契约破坏` 必须修，`需补强` 必须补交换/铺垫/成本。

### 3. 分批建纲（剧情批滚动）

默认先建前 10 章后**停靠**，报告「已可开始写第 1 章」；只有用户明确要求写正文才进入正文。规则：一批≈一个剧情单元（5-15 章），>10 章拆两批；首批=前 10 章封顶可跨单元；写到单元末段（剩余未建细纲≤2 章）即滚动补下一单元整批。每批补纲前先写「批次定位与阶段约束」（本批可释放/严禁提前释放信息、章尾钩子边界）。批末统一核对「预算合计」Σ∈[章目标,×1.1]，并跑 `scripts/check-outline-retention.js` 留存硬门（收变开三字段）。不在单次对话强行产出 30 章；≤30 章的短书可一次建完。

### 4. 逐章细纲（完整模板）

```markdown
## 细纲（第 N 章）

### 第 N 章：{章名}
- 核心事件：{一句话；供日更与导入统一消费}
- 字数目标：{X} 字（纯字口径＝汉字数不含标点）
- 阶段位置：{开篇/发展/高潮/收尾期；第X阶段第Y章；本章在阶段内承担什么}
- 单元ID/位置：{卷纲剧情单元ID；单元内第几拍/承担功能}
- 目标情绪：{前状态→后状态；不得只写标签}
- α点（目标→障碍→代价 + 情绪弧线）：{目标(≥15字)→关键障碍→代价；情绪弧线 起点→终点}【逐字段溯源见下】
- 主角目标/关键选择：{要什么；必须做的判断/选择}
- 章节定位：{高压/推进/修炼试错/关系回收/低压生活/信息整理；留空按推进章}
- 本章结构公式：{节点1(目的)+节点2(目的)+…}
- 章首钩子：{章首7式之一；低压章可写弱钩子}
- 爽点：{显性爽点；低压章可写"无显性爽点，功能是…"}
- 爽点五字段（角色/类型/级别/蓄力目标/蓄力进度）：{显性爽点逐字段填；无则"无"}
- 本章兑现（收一个）/ 状态变化（变一个）：{章前→章后}
- 本章禁止提前释放：{或"无"}
- 复沓锚句：{无；或精确登记须回环的誓言/提示/引文}
- 契约风险：{契约安全/需补强/契约破坏}
- 逐章审查字段（接管自粗纲让渡，无则标「无」）：humor_check（幽默密度按约定）/ stance_check（角色不得直说作者观点）/ transcendence_check（禁止伪深刻、虚伪和解）/ worse_off（主角处境是否比章前更糟或付出代价）/ stakes_tags（本章赌注标签：目标/身份/关系/资源/秘密）

#### 内容概括（五段式）
- 起因/发展/转折/高潮/结尾：{结尾写落到谁的具体动作/画面/台词，不写状态判词}

#### 情节安排（多线）
- 主线推进 / 副线推进（`SP-XX · 功能 · 本章推进什么`；多副线分行；无则"无"）/ 事件线或任务线 / 任务卡点（可"无"）/ 事件素材数校验（S公式）/ 感情线或关系线 / 逻辑线（原因→行动→结果→后果）

#### 人物关系和出场顺序
- 出场顺序 / 人物关系变化（章前→章后）/ 视角·信息差（谁知道什么、读者知道什么、主角误判什么）

#### 情节细化
- 情节点序列：每点标 密/疏 + 字数预算（密≥250、慢镜头爽点400-600、疏≈40、铺垫120-150；均为纯字口径）；Σ∈[章目标,×1.1]，**建议合计落在区间上半段（≈目标×1.05-1.1），为正文执行留纹理余量**；末尾写 `预算合计：X字`；每点写"谁做了什么+功能标签"
- 任务卡点说明（若办事被卡住，标清功能标签）
- 行动成本（可无）/收益归属：{谁付成本、收益归谁、是否留后续账}

#### 结尾设定和钩子
- chapter_question / hook_chain_status / 结尾设定 / 章尾余势（开一个，强中弱）/ 章尾钩子（章尾13式之一）
```

### 5. α点三要素的逐字段溯源（第五组 B1，软溯源）

α点三个要素各附「应引用字段」（软溯源，不机械校验，但缺了要在草案标注）：

| α点要素 | 应引用设定字段 |
|---|---|
| goal（目标） | `设定/角色/主角.md` 的欲望线（desire_line）；粗纲 core_task |
| obstacle（障碍） | 对手 `行为反差矩阵`（behavior_contrast_matrix）；粗纲 antagonist_manifestation |
| cost（代价） | 主角 `核心恐惧`（core_fear）/ 心结（knot）|
| emotion_arc（情绪弧） | 粗纲 `arc_stage_structure_map` 的心路阶段情绪循环 |

### 6. 三张对齐校验表（第五组 B2/B3/B4，α点与补充事件自检）

**A. α点-心路阶段对齐**（终点情绪是否符合该阶段）：

| 心路阶段 | 终点情绪应有特征 | 不匹配示例 |
|---|---|---|
| 困兽期 | 心结加固、无力、逃避 | 以胜利/希望收尾 |
| 萌芽期 | 一丝希望、尝试欲 | 以彻底绝望收尾 |
| 拉锯期 | 反复摇摆、自我怀疑 | 以坚定信念收尾 |
| 决心期 | 信念形成、行动决断 | 以犹豫退缩收尾 |
| 新生期 | 心结解开、内在和解 | 以再次被困收尾 |

**B. α点-爽点预判对齐**：预判爽点章（来自粗纲 highlight_preset）的 α点戏剧强度须撑得起爽点类型与级别；蓄力章须有「为后续爽点蓄力」的微悬念/需求压制，引爆章须有「引爆瞬间」，余韵章须有「消化镜头」。

**C. 补充事件库按心路阶段对齐**（S 不足补事件时）：

| 心路阶段 | 适合补的事件 | 应避免 |
|---|---|---|
| 困兽期 | 世界观展示、内心反思、节奏缓冲 | 冲突升级（尚在铺垫）|
| 萌芽期 | 关系深化、冲突升级（微小试探）、伏笔强化 | — |
| 拉锯期 | 冲突升级、关系深化、内心反思 | 节奏缓冲过多 |
| 决心期 | 冲突升级、关系深化、伏笔回收 | 节奏缓冲（除非决战前宁静）|
| 新生期 | 内心反思（信念整合）、节奏缓冲、世界观展示 | 冲突升级（除非余波）|

### 7. 细纲节奏检查（G5.3，每章必答）

- 7 项基础：①开头有阅读理由②一次明确目标推进/关键选择③章内情绪有起伏④章尾落未解决问题/推进余势⑤爽点完成蓄力-引爆-余韵闭环（不硬造）⑥高压章给压力来源⑦与上下章钩子真实承接。4 项豁免：纯过渡/信息整理/低压生活/开篇背景章可豁免②⑤，但须满足①④。
- 爽点-紧张值阈值：minor≥5/medium≥7/major≥9/高潮=10（TP-08 全篇唯一）。
- **四部分事件密度 + 空白章校验（第五组 B5）**：批末轻量校验四部分事件密度与空白章率（快/中/慢节奏阈值见 references），空白章标注「设计性留白 or 数据性空章」，超阈值按补充事件库补。
- **关系变化节点保护（第五组 B6）**：关系变化触发章紧张值取高、豁免「连续高压」检查；节奏调整优先保护关系变化节点的情绪铺垫，不牺牲人物弧线转折。

### 8. 章节标题 + 细纲后设定补全 + 落盘

- 章节标题轻量去重，细纲标题与正文文件名一致。
- 细纲后设定补全：扫描本批新出现的会复用势力/设定 → 建 `设定/势力/{名}.md`、`设定/世界观/{主题}.md`（增量补充不覆盖；一次性路人/无戏份配角不建档）。
- **人物增量补人流程**（人物不与势力/世界观混同建档）：
  - **主线级新人物**：不在此层造——标「欠账点」回粗纲/卷纲，经卷纲/粗纲确认进入后由 `story-character-lab` 增量补人模式补设计。
  - **非主线会复用配角**（本批新出现、后续会再用、非主线承载者）：路由 `story-character-lab` **增量补人模式**——层级判定（判断显式化三段式）→ 代号分配 → 按层 G3.x 标准逐子步骤深度设计 → 建 `设定/角色/{类型编码}_{人物名}.md` → 登记 `_人物框架.md`（含 `faction_arc` 与出场密度重算）→ 局部核查。**禁止只写一份速记卡即算补全，禁止沿用 `{名}.md` 无编码命名。**
  - **已有人物需修改**：不在细纲内就地改人设——按跨产物修订门禁路由 `story-character-lab` **改人模式**（影响分析 → 受影响模块重设计 → 局部核查），完成后核对本批细纲是否受影响。
  - 补人/改人全部完成后才落盘本批细纲并停靠；停靠报告须列明本批新增/修改的人物、层级与代号，并注明「已可进入场景卡/正文」。
- 落盘：`大纲/细纲_第NNN章.md`（本 skill 唯一正式产物）。前 3 章额外加载 `references/opening-design.md`（黄金三章）。
- **停靠**：细纲交付后停止，报告「已可进入正文/场景卡」。不自动写正文、不自动产场景卡。
