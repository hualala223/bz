# story-constraint-gate：前序成果约束清单门

## 定位与守门

- **机制来源**：用户自有《小说设置提示词》第四组 G4.0、第五组 G5.0、第六组 G6.0 共同的「第零步：前序成果全量扫描」协议（遍历前序产物 → 字段分 A 硬约束/B 软约束/C 元数据 → 约束清单逐条向用户报告 → 确认后继续），适配 oh-story 目录约定，属用户本人资产。
- **何时执行**：作为 `story-long-write` Phase 3（大纲搭建）的步骤 0 自动运行；`story-scene-card` 步骤 0 读取其产物；用户显式要求「出约束清单」时单独运行。
- **守门**：任何下游阶段（卷纲/细纲/场景卡）不得在约束清单未确认的情况下大面积偏离设定；A 类硬约束是「不得违反」的，B 类软约束是「默认遵循、可协商」的。
- **不新增权威**：本门只产出 `大纲/_约束清单.md`（规划态视图），不创建第二个结构化权威；设定阶段权威仍是 `设定/_开书.json`，正文阶段权威仍是 `追踪/_tracking-state.json`。

## 流程

1. **扫描源**（按存在性依次读取；缺失源跳过，并在报告开头注明「未发现 {源}，跳过」）：
   - `设定/_开书.json`（第一优先级——设定阶段唯一累积权威，字段路径以此为准）
   - `设定/*.md`（故事蓝图 / 主题 / 题材定位 / 世界观/* / 关系 / 文风 / 角色/_人物框架 等，按实际存在读取）
   - `选题决策.md`（若存在于项目根或 `设定/`）
   - `对标/` 摘要（详细对标数据在 `对标/`，摘要节在 `设定/题材定位.md` 的「对标分析」）
   - `追踪/上下文.md`（若已写正文，读当前续写状态约束；未开写则跳过）
2. **字段分类**（自动分类规则表，用于把扫描到的每个字段归入三类）：
   | 类别 | 判定标准 | 典型字段 |
   |------|---------|---------|
   | A 硬约束 | 影响主线结构/冲突/闭环/契约的配置值；改动会破坏已确认设定或伏笔承诺 | length_params（总章数/每章字数）、volume_structure、核心冲突、theme_statement/theme_values、world_rules/碰撞点、reader_contract、金手指限制与伏笔承诺、升级台阶与终局底牌、主角心结、时代锚点 |
   | B 软约束 | 影响风格/节奏/调性的偏好；可协商但不建议随意偏离 | 基调/腔调、幽默密度档、场景类型偏好、出场密度偏好、五感/意象偏好、读者契约的次要期待 |
   | M 元数据 | 不参与内容判定的管理信息 | 项目暂定名、自动扩展模式、_meta 版本/日期/pending_fields、blocked 状态 |
3. **逐条报告**：按 A → B → M 顺序输出约束清单表格，每条含：约束 ID（A-01、B-01、M-01…）、来源（文件路径 + 字段路径，路径对照见 [references/field-mapping.md](references/field-mapping.md)）、约束内容、对下游的影响。**硬阻断：必须逐条列出全部扫描到的约束字段，不得概括、不得省略、不得只贴文件名、不得只展示示例。** 字段已缺失但下游必需的，列为「待补」并说明期望来源。
4. **确认**：请用户确认清单。用户可逐条改分类/增删/升降级；说「直接确认/快速/就这样」则一次通过。任一条被否决 → 更新该条后重列，再继续。
5. **落盘**：写入 `大纲/_约束清单.md`（版本号 + 扫描源的版本/时间 + A/B/M 三表 + 待补记录）。
6. **变更保鲜**：`设定/_开书.json` 的 `_meta.modifications` 发生变化时，提示重跑本门刷新清单（`大纲/_约束清单.md` 版本 +1）；正文开始后，A 类硬约束转为写作期的「不得违反」检查依据（由日更/场景卡流程引用）。

## 产物

- `大纲/_约束清单.md`：唯一产物（人类可读 + 供下游机械引用）。结构：

```markdown
# 约束清单（第 {N} 版）
> 生成时间：{} ｜ 扫描源版本：{_开书.json 版本/存在源清单} ｜ 确认：{已确认/待确认}

## A 硬约束（不得违反）
| ID | 来源（文件.字段路径） | 约束内容 | 下游影响 |

## B 软约束（默认遵循，可协商）
| ID | 来源（文件.字段路径） | 约束内容 | 下游影响 |

## M 元数据
| ID | 来源（文件.字段路径） | 内容 |

## 待补
| 字段路径 | 期望来源 | 影响下游 |
```

- 字段路径字典：`references/field-mapping.md`（提示词 JSON 路径 ↔ oh-story 产物字段声明，供逐条报告与未来机械校验使用）。

## 交棒

- 完成后提示：后续阶段将按 A 硬约束逐项校验（粗纲四张表、细纲每章、场景卡逐场景）；设定若变更，先重跑本门刷新清单。
