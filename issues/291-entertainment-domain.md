# 票 291：娱乐域改版（原影院域）——类型体系/国家/题材/集数/感想导出

标签：ready-for-agent ｜ ADR：docs/adr/0127-entertainment-domain.md ｜ 术语：CONTEXT.md「娱乐」及五个新词条 ｜ 决策来源：grill 两轮 12 问（2026-09-22），用户全部采纳推荐

## Problem Statement

影院域的形态只装得下「看电影」：类型体系是电影/剧集/动漫/纪录片/公开课，没有国家与题材的可选分类（豆瓣抓来的纯文本不算），追剧没有集数概念，看完写下的影评也没有办法导出分享。用户现在把范围扩大到了电视剧、短剧和小说——它需要从「影院」长成「娱乐」。

## Solution

门面整体正名「娱乐」：数据目录迁移到 `我的/娱乐`，顶级类型扩为固定七项（电影/电视剧/短剧/小说/动漫/纪录片/公开课），条目可标注国家（单选）与题材（多选），电视剧/短剧可记追剧进度（总集数/正在看集数，在看卡片显示进度角标），并新增感想导出——列表进多选模式勾选若干条目，一键汇总成一篇 markdown 笔记落盘。旧的剧集组细分 tag 自动归一映射，历史数据零丢失。骨架（域 id、命令 id、设置键、事件通道）全部不动。

## User Stories

1. 作为用户，我要插件里所有看得见的地方都叫「娱乐」而不是「影院/影视」，这样它名实相符。
2. 作为用户，我要我的影视笔记自动搬到 `我的/娱乐` 目录，这样我不需要手动移动几十个文件。
3. 作为用户，我要旧的「剧集」分类自动归为「电视剧」，这样升级后列表不用我逐条重新归类。
4. 作为用户，我要旧的动漫/纪录片/公开课条目保留原分类，这样历史数据不被塞进「其他」。
5. 作为用户，我要给条目标注国家（内地/港台/美国/韩国），这样能按地区浏览自己的观看版图。
6. 作为用户，我要国家待选项里没有的地区可以现场添加，且添加后固定出现在以后每个条目的待选项里，这样不用重复输入。
7. 作为用户，我要在国家筛选里看到「未填」桶，这样能找到旧条目逐个补标。
8. 作为用户，我要给条目勾选题材（悬疑/爱情/年代等），一部作品可以同时命中多个，这样筛选和回顾更贴近内容。
9. 作为用户，我要题材待选项同样支持自定义添加并固定，这样我的私人口味词（如「年代」「群像」）能沉淀下来。
10. 作为用户，我要豆瓣抓取来的题材串被兼容识别成题材勾选，这样旧数据在编辑窗里直接呈现为已选 chips。
11. 作为用户，我要电视剧和短剧在编辑时能填「总集数」和「正在看集数」，这样追剧进度有处可记。
12. 作为用户，我要集数输入只在「在看」状态的剧类条目上出现，这样电影和小说的表单不被无关字段干扰。
13. 作为用户，我要正在看集数追平总集数时收到一个提示，由我自己决定是否标已看，这样不会被自动改状态。
14. 作为用户，我要在看中的剧在卡片上显示 `12/40` 这样的进度角标，这样打开面板一眼看到追到哪了。
15. 作为用户，我要在详情页和表单里看到「感想」这个称呼而不是「影评」，这样对小说条目也不违和。
16. 作为用户，我要通过命令面板一条命令直达感想导出，这样不必先开面板再找入口。
17. 作为用户，我要在列表工具栏进入多选模式、勾选若干条目后一键导出，这样能按年份/题材等筛选组合批量打包感想。
18. 作为用户，我要导出的笔记里每个条目带 名称/类型/国家/题材/评分/观影日期/感想 的完整卡片，这样分享出去别人看得懂上下文。
19. 作为用户，我要导出笔记落到 `我的/娱乐/感想导出/` 且文件名带时间戳，这样多次导出不互相覆盖、可留档。
20. 作为用户，我要短剧/小说不再自动走豆瓣抓取（搜不到白等），但手动「在豆瓣打开」仍然可用，这样不弹失败通知。
21. 作为用户，我要分析页统计自动按新类型体系聚合，这样报告不用改口径就能继续看。
22. 作为移动端用户，我要以上能力（类型/国家/题材/集数/导出）在移动面板同构可用，这样两端口径一致。
23. 作为用户，我想看/在看/已看三态和评分语义保持原样，这样我的使用习惯和数据都不受影响。

## Implementation Decisions

- **门面与骨架分离**（ADR-0127 §1）：显示名/文案/命令显示名改「娱乐」；域 id、命令 id 前缀、设置键、模块目录、smartcat 事件通道 `'movie'` 全部不变。smartcat、home、recap、checkup、diary 流等联动方零改动——影视目录读取已收敛在跨域单点解析函数（ADR-0115），默认值一改全域跟随。
- **数据目录迁移**（ADR-0127 §2）：默认目录 `我的/影视`→`我的/娱乐`，启动时旧目录存在且新目录不存在则整体移动（保持 vault 内链接）；设置里存的是旧默认值时平移。日记侧独立归类键 `movieDirectory` 不动。兼容性冻结由 ADR 授权修订，仅此两处（目录位置、新增 fm 键），旧 frontmatter 字段全部继续可读。
- **顶级类型固定七项**（ADR-0127 §3）：电影/电视剧/短剧/小说/动漫/纪录片/公开课；剧集组退役，七个细分剧 tag 归一映射「电视剧」；未知 tag 仍归「其他」。不开放顶级类型自定义（它牵动集数输入与豆瓣抓取开关等行为分支）。
- **国家**（ADR-0127 §4）：fm 新键「国家」，单值单选 chips；默认待选项 内地/港台/美国/韩国（用户原话「美剧/韩剧」已确认规范化）；行尾「+」自定义并持久化到 data.json 选项池键（同日常收集域分类先例，全局共享）。豆瓣「制片国家/地区」字段独立保留，不参与选项逻辑。筛选条加「未填」桶；不做从豆瓣多值串自动预填（合拍片歧义，宁空勿错）。
- **题材**（ADR-0127 §5）：复用 fm 键「类型」，顿号分隔字符串承载多选；默认待选项 悬疑/爱情/年代；自定义持久化到 data.json 第二个选项池键；豆瓣题材串按分隔符兼容读取。
- **集数**（ADR-0127 §6）：fm 新键「总集数」「正在看集数」（数字，仅电视剧/短剧写入）；表单条件显隐 = 剧类 且 在看；追平只 toast 提示不自动改状态；在看卡片角标显示 `正在看/总集数`。
- **感想导出**（ADR-0127 §7）：新增一条命令（显示名「娱乐： 导出感想」）直达多选模式；列表工具栏另有「多选」入口。导出 = 拼条目卡 markdown 落盘到导出子目录，文件名含时间戳。UI 文案「影评」→「感想」，fm 键「影评」不动。
- **豆瓣抓取收窄**（ADR-0127 §8）：仅电影/电视剧自动入队；短剧/小说跳过队列，手动「在豆瓣打开」保留。
- **分析页最小跟随**（ADR-0127 §9）：统计维度按类型动态聚合自适应；集数画像明确不做（另票）。
- **命令数**：注册表 +1（72→73），冒烟测试命令清单同步。

## Testing Decisions

- **只测外部行为**：frontmatter 进、条目对象出；表单交互进、落盘 frontmatter 出；不测内部拆分函数。
- **沿用既有三条缝，不开新缝**：
  1. 数据层缝（既有 cinema 数据测试，`// @vitest-environment node` 口径）：七项类型映射（剧集细分 tag 归一）、国家/题材/集数解析、豆瓣题材串兼容、旧目录默认值回落；
  2. UI 层缝（既有 cinema UI 测试，jsdom + mock obsidian）：表单条件显隐（剧类×在看）、自定义待选项固定、多选模式勾选与导出落盘路径、卡片进度角标、追平提示不自动改状态；
  3. 冒烟缝（smoke 命令注册表）：新命令 id 在清单中，命令数口径 +1。
- 先例照抄同目录既有测试的组织方式；迁移逻辑用临时 mock vault 断言「旧目录存在且新目录不存在才搬」两分支。

## Out of Scope

- 分析页的集数/追剧进度画像（另开一票）。
- 从豆瓣多值国家串自动预填「国家」。
- 命令 id / 域 id / 设置键改名（明确不动）。
- 域事件通道改名与 smartcat 消费方任何改动。
- 短剧/小说的豆瓣图书接口抓取。
- 动漫/纪录片/公开课条目的任何数据改写。

## Further Notes

- 用户原话「美剧/韩剧」已规范为「美国/韩国」（grill Q3 确认）；题材默认三项起步是用户「等」字的最小解释，扩充靠自定义固定机制。
- 门禁：tsc --noEmit 0 错 + vitest 全量绿 + esbuild production 构建通过；汇报时门禁数字以 vitest 输出行为准。
- 主仓工作区可能带用户未提交改动，动工前先查构建产物状态（main.js/styles.css 勿覆盖未提交内容）；本票不触碰 review/diary 冻结区（ADR-0121）。
