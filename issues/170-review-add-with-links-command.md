# Ticket 170 — 「批量加入复习计划」命令（review add with links）

> 状态：`ready-for-agent`（2026-09-08，源自 grilling 设计树，两轮已对齐，用户确认）

## Problem Statement

用户视角：我在读某篇笔记时，它往往链接着一簇相关笔记（正文双链、frontmatter related 等）。想把这组笔记一起纳入复习节奏时，只能逐篇执行「将当前文档加入复习计划」，一篇篇点既繁琐也容易漏。我需要一个入口把「这一篇和它直接引用的笔记」一次性加入复习计划。

## Solution

新增永久命令「批量加入复习计划」（id `bz-review-add-current-with-links`）：对当前打开的笔记，收集它的**一级出链**（正文链接 + frontmatter 链接，经 Obsidian 链接解析还原为 vault 文件），连同当前文档一起逐篇加入复习计划——已在计划中的跳过不动排期，最后给一条汇总通知。命令面板、快捷键、文档内右键三个表面照常可用。

## User Stories

1. 作为用户，我希望在打开一篇笔记时执行「批量加入复习计划」，把它和它直接链接的笔记一起加入复习计划，以便一组相关笔记一次入列。
2. 作为用户，我希望出链收集覆盖正文链接（`[[...]]` 与 markdown 链接，含别名、标题链接、块引用）和 frontmatter 链接（如 related 字段产生的双链），以便两类关联都算数。
3. 作为用户，我希望只收一级出链（当前文档直接链接到的），以便加入范围可预期、不会一次卷入整个链接图。
4. 作为用户，我希望链接目标按 Obsidian 标准规则解析（最短路径、vault 内唯一匹配），以便和我在编辑器里点链接的跳转结果一致。
5. 作为用户，我希望已在复习计划中的文档（含当前文档本身）被跳过且不重置其阶段/排期/历史，以便批量误触不破坏既有复习进度。
6. 作为用户，我希望结束后收到一条汇总通知（如「已加入 X 篇，Y 篇已在计划中跳过」），以便知道本次批量结果。
7. 作为用户，我希望全部为新加入时收到成功通知、无一新增时收到提示类通知，以便一眼分辨结果性质。
8. 作为用户，我希望断链和指向非 Markdown 文件（图片、PDF 等附件）的链接被静默忽略且不计入汇总，以便通知保持简短。
9. 作为用户，我希望当前文档不是 Markdown 文件时整单被拒绝并提示（与单篇命令同文案），以便不产生无效条目。
10. 作为用户，我希望新加入的条目排期走默认规则（首次复习：1分钟后），并立即参与按数量复习取材，与自动收编、单篇手动加入同权。
11. 作为用户，我希望排除笔记黑名单不受影响（仍只约束监听文件夹自动收编，命令加入不受限），以便手动批量加入与自动排除互不干扰。
12. 作为用户，我希望命令是永久命令，能在命令面板搜到、能绑定快捷键、文档内右键能选到，以便按习惯触发。
13. 作为用户，我希望加入的条目能在「复习条目管理」设置组中看到并可移出（含撤销），以便批量加入的条目同样可清理。
14. 作为开发者，我希望出链解析独立成纯函数（输入文档缓存与解析器，输出去重后的文件列表），以便数据层逻辑可脱离 Obsidian 运行时单测。
15. 作为开发者，我希望命令只在 main.ts COMMANDS 表注册一次（id 三段式、卸载全量 removeCommand），以便遵守命令注册单点铁律。
16. 作为开发者，我希望命令数 36→37 的变化同步到 AGENTS.md、smoke 测试断言与 CONTEXT.md，以便文档与实测一致。

## Implementation Decisions

- **入口**：永久命令 `bz-review-add-current-with-links`，名称「批量加入复习计划」；`callback`（命令面板，取 active file）+ `editorCallback`（文档右键）双入口，照搬 `bz-review-add-current` 的注册模式；仅在 main.ts COMMANDS 表注册一次。
- **出链收集**：读该文档的文件缓存，合并正文 links 与 frontmatterLinks 两类链接记录；逐条经 `metadataCache.getFirstLinkpathDest` 解析为 vault 文件（与编辑器跳转同规则），按 linkText 去重；解析失败（断链）与解析结果非 .md 的条目丢弃。
- **一级语义**：只处理当前文档自身的链接记录，不递归出链的出链（用户拍板，递归留作以后扩展）。
- **逐篇加入**：复用既有 `ReviewApp` 数据管理器 `addItem`（filePath 判重，重复抛错）——批量版在应用层先查重跳过，重复条目不动排期；当前文档非 .md 时拒绝并中止（整单无副作用）；当前文档已在计划中不中止，仍继续处理出链。
- **汇总通知**：一条通知报「新增 X 篇 / 跳过 Y 篇」口径；X>0 用 success 类图标，X=0 用 info 类图标；文案不新增 ICONS 表图标、正文无 emoji 前缀。
- **零 schema 改动**：review.json 格式不变，无新增字段；不改单篇命令 `bz-review-add-current` 的行为与文案。
- **黑名单边界**：`reviewExcludedNotes` 语义不变，批量命令不读写黑名单（CONTEXT.md 既有定语「手动 ➕/命令加入不受限」自然覆盖）。
- **文档同步**：AGENTS.md 命令数 36→37；CONTEXT.md「复习计划」条目补批量加入入口一句；PROGRESS.md 记票；挂 ticket 170。

## Testing Decisions

- 测外部行为而非实现细节：接缝取 review app 层公开方法（项目最高可用接缝，不新增接缝）。
- 覆盖路径：全部新文档 → 全部入列 + success 通知；部分已存在 → 新的入列、旧的不动排期字段 + 汇总通知；全部已存在 → 无写数据 + info 通知；当前文档非 .md → 拒绝且零副作用；断链与非 .md 出链被忽略；frontmatter 链接目标被收集。
- 出链收集纯函数单独测：mock 文件缓存与解析器注入，断言去重、丢弃、顺序。
- 先例：`tests/review/app-add-current.test.ts`（守卫 + 通知文案断言模式）与 data 层 MockVault 注入模式。

## Out of Scope

- 不递归多级出链（一级拍板已定，递归留作以后扩展）。
- 不加加入前确认/勾选弹窗（一键全加已拍板）。
- 不做「移出当前文档及其出链」的配套批量移出。
- 不改按数量复习算法、监听文件夹、黑名单语义；不改 review.json 格式。
- 不动既有 `bz-review-add-current` 命令的行为与文案。

## Further Notes

- 命令 id 是外部裸调用约定，`bz-review-add-current-with-links` 一经发布即冻结，改名需同步。
- 出链解析为本仓库首次使用 `getFirstLinkpathDest`/frontmatterLinks（探查确认全库现无此用法），实现时注意 mock-obsidian-entry 需补齐对应能力。
