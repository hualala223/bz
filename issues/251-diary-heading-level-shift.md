# issue 251：日记标题层级整体上提一级（ADR-0113）

## 需求（用户）

> 把所有的标题都往前提一级，就是二号标题变成一号标题，三号标题变成二号标题

承接 issue 250（日程规划改为按日记模板建文件）的样式基准，用户看过产物后要求把层级整体上提一级。

## 裁定（问答两轮）

| 问题 | 选择 |
|---|---|
| 存量旧日记（`##` / `###` 小节）怎么办 | **兼容旧层级**——读侧按标题文字匹配、层级无关；不批量迁移历史文件 |
| 「每日复盘」模板是否一起提级 | **只提首行**：`## 当日复盘` → `# 当日复盘`；`### 触动点` 及其下 `#### …` 不动 |

## 改动

**写侧（新产物一律新层级）**

| 文件 | 改动 |
|---|---|
| `src/diary/daily.ts` | 骨架兜底 `FALLBACK_DIARY_TEMPLATE` 各级 `#`；`buildPlanContent()` 三段 `##`；`PLAN_HEADING` = `# 日程规划`；`PLAN_MARKER` = `## 代办事项`；`PLAN_TRACK_MARKER` = `## 完成情况跟踪`；`REVIEW_TEMPLATE` 首行 `# 当日复盘` |
| `src/diary/daily-capture.ts` | `ACTIVITY_HEADING` = `# 日常行为记录`；`TODO_HEADING` = `## 代办事项` |
| vault `CONFIG/TEMPLATE/模板-日记.md` | 五个骨架标题同步提为 `#`（其余内容与末尾无换行维持原样） |

**读侧（层级无关，保证旧文件不退化）**

- `src/diary/daily.ts`：新增 `headingLineRe(text)` = `^#{1,6}[ \t]+{文字}[ \t]*$`（整行、任意层级）。`hasPlan(text)` 改为「代办事项 + 完成情况跟踪 两个标题文字同时命中」，不再依赖具体 `#` 数量；`appendPlanToDiary` 的「已有日程规划标题」判定同样层级无关。
- `src/diary/daily-capture.ts`：`insertIntoSection` 新增两轮查找 `findMarkerLine`——精确层级优先，未命中再匹配「多一个 `#`」的旧层级；小节边界改用**命中行的实际层级**（`headingLevel(lines[markerIdx])`），旧文件切分结果与改动前逐字一致。

## 影响与残留

- 新模板下骨架标题与条目标题（`# 📖 HH:mm`）同为一级；`HEADING_RE` 要求时间戳，骨架标题不会被误判为条目标题（ADR-0110 前导区口径不变）。
- 库内将长期并存两种层级（存量文件不迁移），读侧已双向兼容。
- 存量「条目形态」日记（如 `2026-09-10.md`）里 `## 代办事项` 小节归属为条目正文，捕获插行照常命中（命中行层级切分）。
