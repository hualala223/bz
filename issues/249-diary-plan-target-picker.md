# issue 249：日程规划支持「当日 / 明日」（ADR-0111）

## 需求（用户提出）

> 写日记中的「日程规划」功能，需要优化，改成，当点击日程规划之后，会出现两个选项「当日」「明日」，不管是哪个选项，生成的日记文件模版都是一样的，唯一只是日期不一样，一个是当天的日记文件，一个是明天的日记文件。

## 定位（改造前）

`src/diary/daily.ts` 的 `planTomorrow()` 行为写死：`moment().add(1,'day')` → `addEntry(明天, 当前 HH:mm, ['日记'], buildPlanContent())`；入口为命令 `bz-diary-plan`（「日程规划（明日日记）」）与日记面板头部 🗓️。

**顺带查出一个已存在的判重缺陷**：判「该日已有日程规划」用的是 `PLAN_MARKER = '### 代办事项'` 单标记，而 issue 247 的「当日待办事项」捕获（`daily-capture.ts` 的 `TODO_HEADING`）**与它逐字同值**，往当天日记 `### 代办事项` 小节追加行正是它的正常行为。只写明天时问题不显形（查的是明天、写的是今天），**一旦支持「当日」就会当天用过待办捕获 → 判为"已有规划"直接跳过**，新功能上线即哑火。

## 改造（ADR-0111）

- **入口**：新增 `openPlanPicker()`——`openFlowDialog` 两动作「当日 / 明日」，默认焦点落在最后一个动作（明日），回车即改造前旧行为；遮罩 / ESC 按取消语义 `undefined` → 不建任何条目。
- **主流程**：`planTomorrow()` 退役 → `planDiary(target: 'today' | 'tomorrow')`，日期由纯函数 `planDate(target)` 决定；条目标题时间仍取当前时刻（不按目标日期改写），保证两目标产物**除日期外完全同构**。
- **模板**：`buildPlanContent()` 三段（`### 代办事项` / `### 完成情况跟踪` / `### 备注`）**逐字不动**。
- **判重**：收紧为 `PLAN_MARKER` 与新增 `PLAN_TRACK_MARKER`(`### 完成情况跟踪`) **双标记同时命中**，抽出纯函数 `hasPlan(entries)`；待办捕获只写前者，故不再误伤。
- **文案**：已存在提示随目标走 —— `当天（X）已有日程规划，不再重复创建` / `明天（X）已有日程规划，不再重复创建`；创建成功提示不变。
- **命令契约**：`bz-diary-plan` **id 不变**（铁律 2），命令名与面板按钮提示由「日程规划（明日日记）」改为「日程规划」，行为由"一键明日"变为"弹选项"。

## 测试（`tests/diary/daily-flow.test.ts`，17 例全绿）

改造 3 例（原 `planTomorrow` 三例改走 `openPlanPicker()` + `answerByLabel` 应答），新增 4 例：

- 选「明日」→ 明天文件含三段落、今天不建（原例改写）；
- 选「当日」→ 今天文件含三段落、明天不建；
- 取消（`undefined`）→ 今天/明天都不建文件；
- 当日与明日共用同一模板：两次生成的正文（去首行标题）**逐字一致**；
- 回归（ADR-0111）：日记里只有 `### 代办事项`（待办捕获残留）→ 仍创建；
- 当日已规划 → 文案用「当天」而非「明天」。
