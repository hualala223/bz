# Ticket 168 — 复习域「单一入口合并」重构（review single-count entry）

> 状态：`ready-for-agent`（设计已 grill 三轮拍板、seam 已确认；等「开工」命令后按 ADR-0077 实施）
> 分支：`worktree/168` ｜ ADR：0077 ｜ spec：本文件 + spec.md「复习域单一入口合并」节

## Problem Statement

用户视角：复习入口过多。命令面板有 11 个复习命令（复习计划面板、开始复习、加入复习计划、移出复习计划、复习（跳转逾期）、复习（选择难度）、快捷标记 ×4、复习（按数量）），其中「开始复习」与「复习（跳转逾期）」是同一函数（`autoJumpOverdue`）的双入口，面板承载整套计划管理 UI（列表/卡片/抽屉/搜索/归档）。用户实际想要的复习方式只有一种：**按数量做题复习**。多余入口增加认知负担，且把复习路径分裂成「做题」与「普通跳转手动评级」两条。

## Solution

复习域收敛为单一入口「复习（按数量）」：删除复习计划面板与除「复习（按数量）」外的全部 10 个复习命令；把被删功能中值得保留的部分——**设置、逾期监控提醒、监听文件夹自动收编、文件树标记、条目管理**——合并进按数量复习：

- 篇数弹窗新增 ⚙️ 按钮 → 「复习设置」弹窗（新增「复习条目管理」组）；
- 逾期常驻通知「去复习」→ 直接进入按数量复习会话，覆盖**全 vault 逾期笔记**（不再受候选文件夹限制），篇数 = min(逾期数, 每日复习上限)；
- 复习全面做题化；普通复习（跳转手动评级）退役。

## User Stories

1. 作为用户，我希望命令面板只保留「复习（按数量）」一个复习命令（其余 10 个全部移除），以便入口唯一、无歧义。
2. 作为用户，我希望「复习（按数量）」的既有行为完全不变（篇数弹窗、安排算法、逐篇做题、排期写入、汇总页、查看原文档、重做本篇、当天已复习排除），以便复习习惯零打断。
3. 作为用户，我希望旧 review.json 数据原样可读（条目/阶段/排期/历史继续参与逾期与阶段采样），以便数据零损失。
4. 作为用户，我希望能从篇数弹窗直接打开复习设置（⚙️ 按钮），以便在使用的场景旁边配置复习。
5. 作为用户，我希望设置弹窗标题与分组反映新形态（「复习设置」），以便术语与现状一致。
6. 作为用户，我希望「检查提醒」设置保留：到期提醒开关与新笔记加入提醒开关，以便继续控制提醒。
7. 作为用户，我希望有逾期笔记时仍收到常驻聚合通知（60 秒轮询、常驻不自动消失、diff 记忆防刷屏），以便不错过到期复习。
8. 作为用户，我希望点逾期通知里的「去复习」直接进入按数量复习会话，且范围覆盖**全部**逾期笔记（任意目录），以便一键清掉全部逾期。
9. 作为用户，我希望「去复习」会话篇数 = 当前逾期篇数，且受「每日复习上限」约束（超限截断并提示剩余留到下次），以便符合既有节奏语义。
10. 作为用户，我希望「去复习」会话复用与手动按数量复习相同的逐篇做题与汇总页，以便体验统一。
11. 作为用户，我希望手动点「复习（按数量）」命令仍按候选文件夹过滤安排（冻结不动），以便原有手动路径不受影响。
12. 作为用户，我希望做题家设置（出题数/多选题/打乱顺序/出题难度）始终可见可配，以便复习做题化后仍能调整出题。
13. 作为用户，我希望「用做题测难度」开关退役且旧配置残留值被忽略，以便不留死开关。
14. 作为用户，我希望监听文件夹自动加入、删除确认、改名路径跟随、排除名单继续工作，以便复习数据自动收编不中断。
15. 作为用户，我希望文件树逾期染色与到期徽章（文件树标记）继续工作，以便在文件树一眼看出逾期。
16. 作为用户，我希望设置里能查看并管理复习条目（列出全部条目、逐条移出、移出可撤销、挂起记录标灰），以便面板删除后仍能清理复习数据。
17. 作为用户，我希望复习全程做题化后，AI 未配置时得到明确提示（「AI 服务未配置，无法按数量复习」），以便知道原因。
18. 作为用户，我希望复习计划面板（列表/卡片/右键抽屉/搜索/归档/双击打开/难度弹窗）不再出现在任何入口，以便无死 UI 残留。
19. 作为开发者，我希望命令注册表恰好 29 个、无任何 `bz-review-*` 残留（除 `bz-review-count`），以便外部契约清单清晰。
20. 作为开发者，我希望不可达的死代码与死样式类全部清理，以便维护面干净。
21. 作为用户，我希望移动端「复习窗口默认全屏」设置随面板退役而消失（旧值忽略），以便无失效设置项。
22. 作为用户，我希望退役的 10 个命令 id 与删除决定被记录（issues/ADR/PROGRESS），以便知晓变更缘由。

## Implementation Decisions

- **命令注册表**：删除 10 个复习命令（open/start/add/remove/overdue/rate/again/hard/good/easy），仅保留 `bz-review-count`（复习（按数量））；插件命令总数 39→29；卸载全量 removeCommand 机制不变；命令 id 是外部裸调用约定，删除即外部失效（用户已接受）。
- **数据底座**：复习数据模型与 FSRS 算法整体保留（review.json 条目、阶段/排期/历史、待重做、挂起记录语义不变），作为按数量复习与逾期监控的底座；review.json 零格式改动。
- **面板移除**：复习计划面板整体删除（列表/卡片/统一抽屉/搜索/归档/难度弹窗/旧式确认弹窗/ESC 层），UI 模块收缩为「篇数弹窗 + 设置入口」；`reviewMobileDefaultFullscreen` 键与设置行随面板退役（旧值忽略）。
- **篇数弹窗**：新增 ⚙️ 按钮 → 打开「复习设置」弹窗（复用声明式设置 schema，标题由「复习计划设置」更名）。
- **设置 schema**：删除「用做题测难度」开关与其键；做题家子项（允许多选题/每篇出题数量/打乱顺序/出题难度）改为**常显**；删除「移动端默认全屏」行与其键；保留检查提醒 / 复习节奏 / 按数量复习 / 自动化（监听文件夹+排除名单）/ 界面（文件树标记）组；**新增「复习条目管理」组**——列出全部条目（挂起标灰）、逐条移出（确认 → 移除 → toast 撤销恢复）。
- **逾期监控**：启动门控（enableAutoNotify）与 60 秒轮询保留；常驻通知「去复习」action 改为触发「全 vault 逾期按数量会话」。
- **新增会话入口（供「去复习」使用）**：全 vault 逾期条目（任意目录、按下次复习时间升序）→ 篇数 = min(逾期数, 每日复习上限||∞)（截断提示剩余）→ 复用现有逐篇做题循环与汇总页。**选择逻辑抽为纯函数**（count 模块，node 可测，与既有的按数量选择函数同风格同文件）。
- **手动路径冻结**：手动「复习（按数量）」命令的候选文件夹过滤、篇数弹窗、安排算法、做题循环、汇总页全不动。
- **监听模块保留**：自动加入/删除确认/改名跟径/排除名单/挖除清理行为不变；仅其列表刷新回调去掉面板调用。
- **死代码清理**：删除旧「开始复习/跳转逾期/手动评级」路径下不可达函数（重做队列循环、普通复习循环、批量出题、结果卡模板等）与面板残留 DOM/样式类，不留不可达代码。
- **数据兼容**：退役设置键（forceQuizForReview、reviewMobileDefaultFullscreen）残留值静默忽略，不迁移。
- **行为后果声明**：复习全面做题化——手动命令与「去复习」均走做题路径，AI 未配置时明确提示；普通复习（跳转笔记手动评级）整体退役。
- **文档**：新增 ADR-0077（单一入口合并的决策与权衡）；CONTEXT.md 修订 5 处术语（复习计划收敛为纯数据层、按数量复习入口描述、到期提醒「去复习」语义、移动端全屏域清单、统一行操作接入域清单）；spec.md 复习章节更新；PROGRESS.md 记票；AGENTS.md 命令数 39→29 同步。

## Testing Decisions

- **好测试的标准**：只断言外部行为——命令注册表、会话流程与排期结果、通知与「去复习」action、设置 schema 结构、选择纯函数的输入输出；不断言内部实现细节。
- **主 seam（行为层）**：复习应用对象 + mock 做题家（jsdom，沿用现有 app 测试模式与做题家注入机制）——覆盖按数量会话、去复习会话、逾期检查通知绑定、评级排期写入。
- **次 seam（纯函数层，node）**：count 模块现有纯函数原样测试 + 新增「全 vault 逾期 → 选择结果」纯函数直测（含每日上限截断、目录无关性）。
- **注册 seam**：smoke 测试命令清单快照——恰 29 个、无 `bz-review-*` 残留（除 `bz-review-count`）。
- **schema seam**：设置 schema 结构断言——「用做题测难度」行与移动端全屏行消失、做题家子项常显、新增条目管理组存在。
- **保留 seam**：监听/数据/FSRS 测试基本原样（监听模块仅刷新回调微调同步）。
- **新增用例**：去复习会话只含逾期且跨目录；每日上限截断与提示；通知 action 触发去复习会话；条目管理移出 + 撤销恢复；篇数弹窗 ⚙️ 入口；命令注册 39→29。
- **先例**：tests/review 现有 10 个测试文件 + smoke 命令快照模式。

## Out of Scope

- 不改 review.json 数据结构与 FSRS 算法（含权重、间隔缩放语义）。
- 不改按数量复习的冻结流程（篇数弹窗/安排/做题/汇总/重做本篇）。
- 不重建任何形式的复习计划列表面板。
- 不动做题家（quiz）域内部实现与数据。
- 不迁移/清理旧数据；不移除其余兼容键（如 reviewStoragePath）。
- 不改监听文件夹/排除名单的行为语义。
- 不涉及跨域 UI/主题适配改动。
