# 258: 吸收第一块 —— 通知四项横切偏好

**What to build:** 使用者在设置页的「🔔 通知」分组里能调四项通知偏好——通知级别（降噪）、停留时长档位、桌面弹出位置、同屏上限。四项**都未改动**时，通知行为与加入偏好之前逐条一致；改动后立即生效。这是吸收上游增量流程的第一块，用于把「摘取 → 按本地形态落位 → 补测试 → 过门禁」整套流程跑通一遍。

**Blocked by:** 257（基线落定）——按 ADR-0120 的起步纪律，基线不干净时吸收的 diff 无法单独审查。实际执行时先行开发、门禁通过，基线落定后再成条提交。

**Status:** 已交付 —— 提交 `014d5e02`（7 文件，+465 / −15）；仅提交本块自身改动的 7 个文件，未触碰工作区其余未提交内容

## 交付内容

- **四个设置键**（沿用上游键名——两侧无命名分歧，ADR-0118 的例外）：通知级别（`all` / `important` / `error`，缺省 `all`）、停留时长（`quick` 2 秒 / `standard` 3 秒 / `relaxed` 5 秒 / `persistent` 点击才关，缺省 `standard`）、弹出位置（四角，缺省 `top-right`）、同屏上限（`3` / `5` / `8`，缺省 `5`）。**四项缺省值均等于加入偏好之前的既有行为。**
- **「🔔 通知」分组**按本地既有形态接入主设置页：无 icon = 区块标题平铺（与 AI 组同），不引 icon 字段、不改既有组头版式、不新增独立导出；插入位置在「📂 数据存储路径」之后、域组之前。
- **通知模块的偏好读取通道**：走既有设置读取接口，不新增全局状态、不挂 window；provider 未注入或抛错一律按缺省行为走——通知是最后兜底的报告通道，设置读不到时更不能哑掉。**模块对外导出面未变，零调用方改动。**
- **四个既有消费点接入**：级别门控（静默先于去重登记，被静默的调用视同未发生）、单条停留时长、弹出位置、同屏上限。带操作按钮的通知与进度类型永不被静默（撤销是反悔窗口、进度是长任务状态框）；显式时长不随档位缩放；常驻档的普通帧仍参与堆叠驱逐（区别于进度常驻帧的免疫，P1-33 语义保持）。
- **位置样式**写进 core 层样式源头（铁律 8），角位规则限定在桌面断点内，移动端顶部居中不被覆盖；左列角位入场变体换为从左滑入。

## 需要使用者知道的两处「碰到既有文件」

1. **两处既有测试的断言随新增分组跟改**（非功能变更）：`tests/core/settings-schema.test.ts` 与 `tests/settings-tab.test.ts` 都断言主设置页的区块标题清单**逐字相等**，新增第三/第四个区块标题后必然不符。跟改内容仅为「清单里补上新标题」，既有两组的结构、顺序与其余断言一字未动。
2. **新增分组不会出现在设置面板的「通用」页**：面板的通用加载器按组名硬过滤（只保留数据存储路径组），通知属核心横切项、不建业务域，故只进原生设置页。这与 spec 的决定一致；日后若要让通知进面板，另立票。

上游同名的通知测试比本地多四组（级别 7 / 时长 5 / 位置 4 / 上限 2 例）。本地按「取并集」补足，并额外锁住四条本地既有约束：常驻进度帧不被挤出（P1-33）、被静默调用不占去重窗口、provider 抛错不炸通知、常驻档普通帧仍可驱逐。既有 33 例断言语义未改。
