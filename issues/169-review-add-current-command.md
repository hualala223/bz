# Ticket 169 — 「将当前文档加入复习计划」命令（review add current）

> 状态：`已交付`（2026-09-08，单切片合并 master）
> spec：本文件（源自 grilling 设计树，Q1–Q8 已对齐）

## Problem Statement

用户视角：按数量复习的取材是「候选文件夹自动挑选 + 监听文件夹自动收编」，我无法指定「就是这一篇，我要复习它」。当我在读某篇笔记、意识到它需要进入复习节奏时，没有任何入口能把它加入复习计划（旧入口随 ticket 168 面板退役而消失）。

## Solution

新增一个永久命令「将当前文档加入复习计划」（id `bz-review-add-current`）：对当前打开的笔记一键加入复习计划，之后该条目正常参与按数量复习的排期与做题流程。命令可在命令面板触发、可自定义快捷键；以 `editorCallback` 形式注册后自动出现在文档内右键的待选命令里。

## User Stories

1. 作为用户，我希望在打开一篇笔记时执行「将当前文档加入复习计划」，把它加入复习计划，以便有针对性地自主选择复习哪些文档。
2. 作为用户，我希望该命令是永久命令，能在命令面板搜到、能绑定快捷键，以便按自己的习惯触发。
3. 作为用户，我希望在文档内右键能从待选命令中选到它，以便不离开阅读场景完成加入。
4. 作为用户，我希望加入成功后收到通知「已加入复习计划，首次复习：1分钟后」，以便知道条目已入列及首次排期。
5. 作为用户，我希望对已在计划中的笔记重复触发时只提示「已在复习计划中」，不重置其阶段/排期/历史，以便误触不破坏复习进度。
6. 作为用户，我希望对非 Markdown 文件（附件等）触发时被拒绝并提示「仅支持 Markdown 笔记加入复习计划」，以便不产生无法复习的无效条目。
7. 作为用户，我希望加入的条目立即参与按数量复习的取材与排期（与自动收编条目同权），以便下次复习就能见到它。
8. 作为用户，我希望排除笔记黑名单不受影响（仍只约束监听文件夹自动收编），以便手动加入与自动排除两种表态互不干扰。
9. 作为用户，我希望加入的条目能在「复习条目管理」设置组中看到并可移出（含撤销），以便手动加入的条目同样可清理。
10. 作为用户，我希望通知图标沿用既有 ICONS 表（成功/拒绝不新增图标、正文无 emoji 前缀），以便通知风格一致。
11. 作为开发者，我希望命令只在 main.ts COMMANDS 表注册一次（id 三段式、卸载全量 removeCommand），以便遵守命令注册单点铁律。
12. 作为开发者，我希望命令数 35→36 的变化同步到 AGENTS.md、smoke 测试断言与 CONTEXT.md，以便文档与实测一致。

## Implementation Decisions

- **入口**：永久命令 `bz-review-add-current`，名称「将当前文档加入复习计划」（用户选定 B，非对称命名）；以 `editorCallback` 形式注册，天然获得命令面板 + 快捷键 + 编辑器右键待选命令三个表面；仅在 main.ts COMMANDS 表注册一次。
- **复用底座**：直接调用既有 `ReviewApp.addCurrentToReview`（现无调用方，ticket 168 面板退役遗留）；不改数据模型，review.json 零格式改动。
- **守卫逻辑**：非 `.md` → toast 拒绝；条目已存在（按 filePath 判定）→ toast「已在复习计划中」，不重建不重置；成功 → 复用既有文案「已加入复习计划，首次复习：1分钟后」。
- **通知规范**：图标从 core notice ICONS 表选既有匹配项（成功用 success 类、拒绝用 error/warn 类），不新增图标；正文无 emoji 前缀。
- **黑名单边界**：`reviewExcludedNotes` 语义保持「只约束监听文件夹自动收编」，手动加入不读写黑名单。
- **文档同步**：AGENTS.md 命令数 35→36；CONTEXT.md「复习计划」条目补手动加入入口一句；PROGRESS.md 记票；挂 ticket 169。

## Testing Decisions

- 测外部行为而非实现细节：通过 review app 层公开方法驱动（项目最高可用接缝，无新接缝）。
- 覆盖路径：成功加入产生新条目且首次排期生效；重复加入不产生第二条、原条目排期字段不变；非 `.md` 输入被拒绝且不写数据。
- 命令数断言：smoke.test.ts 同步 35→36。
- 先例：review 域既有 app 层测试（ticket 168 切片留下的条目管理/选择函数测试）作参考。
- 门禁全绿：pnpm test + `pnpm exec tsc --noEmit` + 构建 + diff 自审。

## Out of Scope

- 不加文件右键菜单（File menu）注册、不加 ribbon 图标——`editorCallback` 自带的编辑器右键待选命令已覆盖诉求。
- 不改按数量复习的选择算法、候选文件夹语义、监听文件夹与黑名单行为。
- 不改 review.json 格式、不新增条目来源/类型字段。
- 不做批量加入、不做「移出当前文档」配套命令（条目管理组已可移出）。
- 不为「重复加入重置排期」提供任何路径（已明确否决）。

## Further Notes

- `addCurrentToReview` 的 notice 文案与首次排期为既有行为，验收时以其为准；若守卫逻辑（.md 判定、重复判定）需落在 app 方法内，注意不破坏其他潜在调用方语义（当前无调用方，可自由补强）。
- 命令 id 是外部裸调用约定，`bz-review-add-current` 一经发布即冻结，后续改名需同步。
